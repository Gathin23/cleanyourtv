# TCL 75C645: one-session debloat and launcher notes

Checked on a real 75C645 in one session on 2026-11-10. This is **not** a
several-day tested debloat list: the package set below survived one reboot and
was screenshotted after every batch, but standby/wake, casting and multi-day
stability were not tested. The list is close to `examples/tcl-g03-google-tv`
and `examples/tcl-43c645`; use those as the maintained starting points.

This is the same G03 / BeyondTV4 `V8-R51MT05-LF1V652` AR11 firmware already
covered by `examples/tcl-43c645` (including its 55C645 unit) and by
`docs/devices/tcl-75c63b.md`. It is **not** evidence that every package choice
in those folders is right for a 75C645, and the set below differs from both.

Stock HOME claimants were `com.google.android.apps.tv.launcherx` (priority 2),
`com.google.android.tungsten.setupwraith/.RecoveryActivity` (priority 1) and
`com.android.tv.settings/.system.FallbackHome`. The saved Wi-Fi network belonged
to `android.uid.system:1000`, not setupwraith, so disabling the wizard kept the
TV on Wi-Fi.

### The one package to watch

`com.tcl.usercenter` was disabled here and survived one reboot. The
`examples/tcl-43c645` header records a 43C641 on this firmware that did a full
reboot on every wake from standby with `com.tcl.usercenter` off (#3533). If this
set reboots when the screen wakes, re-enable it first:

```sh
TV_HOST=<tv ip> tools/tv.py 'pm enable --user 0 com.tcl.usercenter'
```

## Launcher

`com.gathin.tvhome` (built with `tools/docker-build.sh`, 587,673 B) is Home.
Dock, left to right: YouTube, Play Store, Plex, TV Settings. `columns` is 4,
`hidden_apps` includes `com.tcl.tv`, `live_tv_package` is `com.tcl.tv`, and the
TCL Settings tile is in `library_apps` because `com.tcl.settings` declares only
a plain `LAUNCHER` activity (`com.tcl.settings/.MainActivity`, which forwards to
`com.android.tv.settings/.MainSettings`).

`HOME_KEY_SERVICE=1` was used. The physical remote was tested by the owner:
YouTube, the gear (keycode 4077, mapped with `settings_key_keycodes` and
`settings_key_panel`), Input (TCL's source panel, no `InputKeyService`), Home,
and a held Volume Up all worked. `consume_volume_keys` is true. The Netflix and
Prime Video buttons do nothing because those apps were disabled.

The launcher's idle clock is on at 10 minutes (`home_idle_clock_minutes` in a
theme overlay); it was verified at 1 minute, where `ClockActivity` appeared after
the remote was left untouched. The system screensaver is
`com.gathin.tvhome/.ClockDream`, and Google's `dreamx` is disabled.

## Verified

After each batch: a screenshot, no crash-buffer entry, Wi-Fi still up, and the
TV inputs still enumerated. After the handover: one row per Down press, Up from
the dock to the top bar, the ends of the top bar stay put, the Inputs dropdown
listed HDMI 1, HDMI 2, AV and Live TV (HDMI 3 and 4 were not exposed by
`TvInputManager` on this unit), Live TV opened `com.tcl.tv/.TVActivity`, HDMI 1
switched and returned Home, all four dock apps launched, Settings opened
`com.android.tv.settings/.MainSettings`, and the idle clock appeared.
After one reboot: sys.boot_completed, all 38 packages still disabled, Home was
`com.gathin.tvhome`, Wi-Fi was connected, the crash buffer was empty, and the
TV booted to Home (FallbackHome → launcher), not Live TV.

Network ADB was then closed: USB debugging and the network-debugging toggle off,
USB authorisations revoked, restart. `tools/adb-closed.py <tv ip>` reported
"the TV refused the connection", and `adb connect` said "Connection refused".
This unit had no Wireless debugging service (`adb_wifi_enabled=0`), so 5555 was
the only port.

## Not tested / known limits

- One session and one reboot; standby/wake, several-day stability, casting,
  Miracast, firmware update and USB media were not tested.
- Netflix and Prime Video were disabled by choice, so their remote buttons were
  not expected to work; neither app was played.
- The Wi-Fi pill shows "Wi-Fi" rather than the network name because Android 11
  only gives an app the SSID when the TV's Location toggle is on. Location was
  left off.
- The launcher's Inputs menu listed the HDMI ports the TV's input list exposes;
  `dumpsys tv_input` showed four HDMI ports in the hardware list but
  `TvInputManager` exposed only two.
- `com.google.android.videos` (Google TV / Play Movies) is off; re-enable it if
  the household uses the movie library.

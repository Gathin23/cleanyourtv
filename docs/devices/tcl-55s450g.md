# TCL 55S450G (G03, US, incremental AR24)

One unit, one session on 2026-11-08. This is not a tested debloat list. The reference
launcher was not installed: the owner chose Projectivy instead. Nothing here was lived
with for several days.

The retail model was identified by the owner as a TCL 55S450G. Android's model
property is `Smart TV`. It is the same G03 / BeyondTV4 / Realtek rtd288o platform
as [`tcl-55s546-us`](../../examples/tcl-55s546-us/debloat.txt) and
[`tcl-g03-google-tv`](../../examples/tcl-g03-google-tv/debloat.txt), on a different
firmware. Do not copy either list onto this build.

| Field | Observed value |
|---|---|
| Product / device | `G03_4K_US_NF_DB` / `BeyondTV4` |
| Board / platform | `RTD2851M` / `rtd288o` |
| Android / SDK | 11 / 30, `ro.tcl.product_type=GTV` |
| Fingerprint | `TCL/G03_4K_US_NF_DB/BeyondTV4:11/RP1A.200622.001/AR24:user/release-keys` |
| Incremental / patch | `AR24` / 2023-03-05 |
| Build date | Wed May 17 2023 |
| ABI | `armeabi-v7a` only |

The 55S546 list is incremental `GTV93` on `G03_4K_US`, not `AR24` on
`G03_4K_US_NF_DB`.

## `APP_AUTO_START`, and no `AUTO_START` op

`appops set <package> AUTO_START allow` returned `Error: Unknown operation string: AUTO_START`.
The op this build prints is `APP_AUTO_START`. While that op read `ignore` for
Projectivy, TclAppBoot refused to bind its accessibility service with
`callee_does't_have_OP_AUTO_START_permission.`

`appops set <package> APP_AUTO_START allow` followed by `appops write-settings`, then
about 20 seconds, survived a reboot and a power cut of 30 seconds. The allow
timestamp printed as about 1271 days ago after the power cut: the clock had fallen
back to the firmware build date until network time corrected it. The mode was
still `allow`.

## setupwraith stayed off once the write had landed

Immediately before `pm disable-user --user 0 com.google.android.tungsten.setupwraith`,
`dumpsys wifi` had no setupwraith owner. Every saved-network creator was
`android.uid.system:1000` (`com.android.tv.settings`). After 25 seconds the package
read `enabled=3`. It was still `enabled=3` after `adb reboot`, after a 30-second
unplug, and after a later reboot in which launcherx was also disabled. Wi-Fi and
ADB came back each time.

An earlier disable of setupwraith did not survive. launcherx was already off, and
the reboot was sent before Android's delayed package-state write. After that boot
launcherx was still disabled and setupwraith was not. That pass is not evidence
that this firmware puts setupwraith back once the write has landed.

Re-enable setupwraith before a factory reset.

## launcherx off, the remote's buttons did nothing

Home activities, in priority order, were launcherx (2), setupwraith (1), Projectivy
(0), and `com.android.tv.settings` FallbackHome. With setupwraith already disabled,
`pm disable-user --user 0 com.google.android.apps.tv.launcherx` made
`cmd package resolve-activity` for HOME return Projectivy. That was still true
after a waited reboot.

The owner then pressed the real remote. The gear button, Input, Netflix, Prime
Video, YouTube, TCL Channel, and Apple did nothing. The TCL Home button still
opened Projectivy's shortcut list. This is not the 55S546 result: that `GTV93`
unit kept Netflix, YouTube, Prime Video, Input, and the gear button working with
launcherx off and no key helper.

`pm enable --user 0 com.google.android.apps.tv.launcherx` brought the buttons
back. The owner pressed Home, Netflix, YouTube, Prime Video, Apple, TCL
Channel, gear, and Input. Home opened Projectivy. The app buttons, gear, and
Input behaved as they had with the stock launcher. A held volume button still
ramped. Casting and HDMI playback both worked.

The system Home activity was launcherx again as soon as it was enabled. An
injected `KEYCODE_HOME` resumed launcherx. The real Home button did not. An
injected key is not the check for this button.

## What else was touched

`pm disable-user --user 0` was used, and only these stayed disabled at the end
of the session:

```text
com.tcl.tv.tclchannel
com.tcl.tv.plus
com.tcl.messagebox
com.google.android.videos
com.google.android.tungsten.setupwraith
```

With the first four off and launcherx still drawing Home, the sponsored banner,
Top picks, Continue watching, and the priced movie row were all still there.
That is not a list to copy. `com.tcl.channelplus`, `com.tcl.waterfall.overseas`,
`com.tcl.dashboard`, and `com.tcl.partnercustomizer` were not disabled.
`com.tcl.partnercustomizer` staying enabled did not keep the remote's app
buttons working once launcherx was off.

# Tested 2026-10-21 on a real unit: applied in five batches with a screenshot after each (29/29 disabled at first,
# plus the stock launcher via launcher/build-and-install.sh), then rebooted once: nothing came back
# enabled. After the changes Settings, Wi-Fi, the launcher's Inputs menu (HDMI 1-3, AV, Live TV via
# TvInputManager; Live TV opens com.tcl.tv/.TVActivity), app tiles, and every button on the real remote
# (Home, Input, Settings, app buttons, Back) worked. The set powers on to the last source, so after a
# reboot from Live TV it shows Live TV, not Home. Not yet lived with for days.
#
# Second unit, Türkiye (model code F8), same AR05 fingerprint, tested 2026-10-24: this list (minus the group 4
# apps it did not have) plus the stock launcher, rebooted twice, and nothing came back at boot. But the kept
# com.tcl.versionUpdateApp is also TCL's silent app store: 15 s after the launcher's `pm install` it installed
# an update of com.tcl.waterfall.overseas, and the update left that package enabled again (`dumpsys package`
# shows enabled=0 with lastDisabledCaller: com.tcl.versionUpdateApp). Check `pm list packages -d` after any
# install, or hide the TCL Channel tile with the launcher's hidden_apps, or disable the updater as well, as
# that owner chose to, which also stops firmware updates.
# com.tcl.guard is a PERSISTENT system-uid app: after `pm disable-user` its tile goes, but its process still
# starts at every boot, as does the factory-disabled com.tcl.smartalexa.
#

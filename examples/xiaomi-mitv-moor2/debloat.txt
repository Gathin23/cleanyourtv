# Package names that differ from the repo defaults on this firmware:
#   stock launcher   com.google.android.apps.tv.launcherx   (NOT com.google.android.tvlauncher)

# Apply:   TV_HOST=<tv ip> tools/disable.sh examples/xiaomi-mitv-moor2/debloat.txt
# Undo:    TV_HOST=<tv ip> tools/restore.sh examples/xiaomi-mitv-moor2/debloat.txt com.google.android.apps.tv.launcherx

# Tested: all 22 packages below are disabled on this TV (`pm list packages -d` confirms it) with the

# under DO NOT DISABLE were ruled out by reading dumpsys, not by disabling them and seeing what

#     set-home-activity .home.HomeActivity, com.gathin.tvhome disabled) with the rest of the list still

#   - The Settings button died once launcherx was off, as described below; enabling HomeKeyService alone

#   - The optional "second round" at the end of this list was also disabled and lived with on this TV.

# Remote buttons once launcherx is disabled (that second TV; `dumpsys window policy` lists who gets
# each global key, logcat shows what happens):
#   Settings   KEYCODE_SETTINGS (176) goes to com.xiaomi.android.tvsetup.partnercustomizer, whose
#              GlobalKeyReceiver starts launcherx's .dashboard.DashboardActivity. With launcherx off that
#              throws ActivityNotFoundException; after a few presses Android marks the process "bad" and
#              drops every key it handles (176, 178 TV_INPUT, 192) until a reboot.
#              Fix: HOME_KEY_SERVICE=1 launcher/build-and-install.sh - it takes the Settings key first and
#              opens Settings, so the receiver never runs.
#   YouTube    KEYCODE_BUTTON_3 (190) is routed to launcherx only, so it does nothing. Fix: add
#              190:com.google.android.youtube.tv to app_keys in config.xml and install with
#              INPUT_KEY_SERVICE=1.
#   Input      KEYCODE_TV_INPUT (178) also goes to partnercustomizer. INPUT_KEY_SERVICE=1 sends
#              com.android.tv.action.VIEW_INPUTS instead, which com.mitv.livetv/.input.SelectInputActivity
#              answers with the same input panel.
#   Xiaomi TV  KEYCODE_BUTTON_5 (192), partnercustomizer again: it starts com.mitv.livetv, which reopens
#              the last input used (an HDMI port, not a tuner). Expected, no change needed.

# ---------------------------------------------------------------------------------------------
# ONLY AFTER com.gathin.tvhome IS INSTALLED. Do not apply this section on a fresh run, or the
# Home button has nowhere to go.
#
# Disabling the stock launcher is not enough on this firmware:
# com.google.android.tungsten.setupwraith also answers HOME - .MainActivity at intent-filter
# priority 4 and .RecoveryActivity at priority 1 - and an ordinary app cannot outrank it, because
# Android ignores android:priority on HOME filters for non-system apps and `cmd package
# set-home-activity` reports Success without taking effect (not even across a reboot). Disabling
# the setupwraith PACKAGE is what frees the slot; `pm disable-user` on its individual components is
# refused with a SecurityException. See docs/TROUBLESHOOTING.md,
# "The new launcher still doesn't own Home".
#
# Trade-off: setupwraith is the first-run setup wizard. Everyday use is unaffected, but re-enable it
# before a factory reset - tools/restore.sh does that for you while this line is in the list.
com.google.android.tungsten.setupwraith   # setup wizard; blocks a third-party launcher from Home

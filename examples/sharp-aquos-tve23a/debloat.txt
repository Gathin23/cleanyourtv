# Remote (SHARP SOLAR RCU, Bluetooth HID). Keycodes read from `dumpsys activity broadcasts history`
# (GLOBAL_BUTTON extras), since the vendor .kl is not readable from the shell:
#   Input   usage 0x0c0091 -> handled by the firmware (Google's input switcher), works with no helper
#   Netflix usage 0x0c0078 -> KEYCODE_STEM_1, firmware opens Netflix, works with no helper
#   YouTube usage 0x0c0077 -> KEYCODE_TV_INPUT_COMPOSITE_1, MediaTek hotkey dispatcher opens
#                             com.google.android.youtube.tv only; mapped to SmartTube with app_keys
#                             (KEYCODE_TV_INPUT_COMPOSITE_1:org.smarttube.stable)
#   Gear    usage 0x0c0040 -> KEYCODE_STAR, CVTE dispatcher toggles the notification handler panel, which
#                             only launcherx answered; settings_key_keycodes 17 opens Settings
# Both mappings need HOME_KEY_SERVICE=1. With it bound, a held volume key moves one step instead of
# ramping (the trade in docs/devices/tcl-55p71b-g09-key-repeat.md); consume_volume_keys did not help,
# because the window policy applies the volume before the helper sees it. The owner kept the buttons.

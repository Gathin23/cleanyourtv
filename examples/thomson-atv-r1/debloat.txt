# Thomson ATV R1 TV stick, Russia, built by SCBC (ro.product.model "ATV R1", ro.product.device R1,
# ro.product.manufacturer SCBC), Realtek, Android TV 9 (API 28), build PTT1.210114.001.
# Wi-Fi only: no USB host (dumpsys usb reads host_connected=false) and no eth0.
#
# Apply:   TV_HOST=<tv ip> tools/disable.sh examples/thomson-atv-r1/debloat.txt
# Undo:    TV_HOST=<tv ip> tools/restore.sh examples/thomson-atv-r1/debloat.txt
#          (run from the repository root; everything is disabled, never uninstalled).
# Comment out any line you want to keep.
#
# Stock launcher: com.google.android.tvlauncher (plain Android TV, not Google TV; restore.sh and
# build-and-install.sh defaults work). The only other HOME claimants are com.realtek.tv.settings' and
# com.android.tv.settings' FallbackHome. setupwraith is installed but does not claim HOME, so no
# RecoveryActivity handover trap. This firmware answers cmd package set-home-activity with Success
# while still resolving Home to the stock launcher; Home only moves after tvlauncher is disabled
# (com.gathin.tvhome then answers HOME and survives a reboot - launcher/build-and-install.sh's order
# covers this, since it disables the stock launcher only once the new one is installed and enabled).
# Live TV: the inputs and tuners come from com.realtek.dtv, com.realtek.tv.atv, com.realtek.tv.atsc,
# com.realtek.tv.isdb and com.realtek.tv.passthrough; the source menu is com.realtek.tv.settings.
#
# Kept on purpose, do not disable:
# - com.google.android.tungsten.setupwraith: the saved Wi-Fi network belongs to it (dumpsys wifi
#   shows cname=com.google.android.tungsten.setupwraith); disabling it deletes the network and takes
#   the stick off Wi-Fi and ADB. Forget the network in Settings, re-join it, then it can go.
# - com.google.android.videos (Play Movies): not asked about on this unit.
# - com.google.android.apps.mediashell (Chromecast built-in) and com.creative.fastscreen.tv
#   (Miracast/FastCast): the owner uses both.
# - com.realtek.keyinterceptserver, com.apps.virtualkey, com.apps.fivekey, com.apps.smartkey,
#   com.apps.sys, com.apps.bluetoothremote, com.functions.autopair,
#   com.google.android.presetup.bluetoothpair: remote keys and Bluetooth pairing.
# - Factory packages, never launched and never touched: com.apps.factory.ui,
#   com.realtek.factorytools, com.rtk.engmenu. EngMenu answers nothing safe and opens the factory
#   menu, and the stock App library offers it as a plain tile; the shipped config.json hides it and
#   its two siblings from the launcher through library_excluded_apps. On CVTE-family boards opening
#   a factory menu flips a flag adb cannot undo; the same care fits this SCBC board.
#
# Re-enabled after the first pass, at the owner's request: com.google.android.katniss,
# com.google.android.speech.pumpkin, com.google.android.tts and com.google.android.tv.remote.service
# (voice search kept; on this Realtek build remote.service holds AtvSearchAssistantService, which
# answers the remote's mic button - the same finding as examples/thomson-43rt1055). Their lines
# below are commented out with this note.
#
# Firmware updaters com.apps.ota and com.apps.authota ship commented out below: they stay enabled
# in this shared list, so no one loses automatic updates by surprise. The owner's unit has both
# disabled, who weighed losing updates against a stick that phones no one at night; pm enable
# --user 0 com.apps.ota (and .authota) undoes it there.
#
# Applied and checked on a real unit on 2026-11-20, in six small batches with a screenshot after
# each, then rebooted: no package came back, Home boots to com.gathin.tvhome, YouTube plays, the
# remote's D-pad works, and the library no longer offers EngMenu. Network ADB on port 5555 closes
# by itself once debugging is switched off in Developer options and the stick reboots.

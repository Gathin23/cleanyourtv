# Vidda C1S 4K laser projector (Hisense sub-brand; device MT9669, board m7642), Android 9,
# build PPR2.180905.006.A1 (02.02.60.02), VIDAA 6.6, China JuUI. 3.6 GB RAM, 1080p UI.
# Same com.jamdeo.* / com.hisense.* namespace as examples/vidda-mt9653/, an older and
# stricter firmware: several of its locks are documented below.
# Stock launcher: com.jamdeo.tv.vod (聚好看 JuUI). It STAYS ENABLED on this list — see
# the Home-key note. The C1S kept 聚好看 as Home; on the C1 unit (below) the reference
# launcher took the Home key with 聚好看 still enabled, see README.md in this folder.
#
# Apply:   TV_HOST=<projector ip> tools/disable.sh examples/vidda-c1s-mt9669/debloat.txt
# Undo:    tools/restore.sh examples/vidda-c1s-mt9669/debloat.txt
# Everything is DISABLED, not uninstalled. Comment out any line you want to keep.
#
# ADB: unlike the MT9653 sets, ro.adb.secure=1. Turning on debugging shows "允许 USB 调试吗?"
# on screen and the host's key must be confirmed there (勾选一律允许) before adb works.
#
# The firmware ships a package install blacklist (settings global install_black_list; it
# names Dangbei launcher, IPTV loaders, TVBox forks), but it is not enforced on adb
# installs — sideloading works. Launchers are fought differently: PackageManager keeps
# resolving HOME to com.jamdeo.tv.vod no matter what. cmd package set-home-activity
# reports Success and writes a preferred record (dumpsys package shows it), yet
# resolve-activity and real Home launches still return the stock launcher.
# persist.vt.use_home_pkg is shell-writable here but empty by default and the Home key
# ignores it.
#
# Home key: third-party accessibility services receive window changes for ordinary apps
# but NONE for com.jamdeo.tv.vod — Aerial's unpatched Home Guard never sees 聚好看 come to
# the front (the binding is not deaf: events for other apps arrive; only the launcher is
# shielded). UsageStats still records its MOVE_TO_FOREGROUND with the right class, so
# Aerial works once foregroundCheck runs on every Android version instead of SDK <= M:
# one-line patch proposed upstream in pengchujin/aerial-tv#545 (applies to 1.47). With
# that build, Home from any app lands on 聚好看 and is brought back to Aerial in about a
# second; boot goes straight to Aerial. Keep the stock launcher enabled — it stays the
# system Home, plays its content from Aerial's grid, and gives the Home key somewhere to
# land that the guard can see. 聚好看 renders normally with both ad sidecars below
# disabled (screenshot-checked).
#
# ⚠ com.hisense.tv.tiletransition is NOT in this list on purpose: it hosts
# TileAnimationService, which the source panel binds to before switching inputs. Disabled,
# picking HDMI does nothing (same as the mt9653 note). Re-enabling fixes it immediately.
#
# Voice is deliberately kept on this list (the owner uses the mic): keylab.speech.view.vidaa
# and the whole com.keylab / iflytek / hisense voice stack stay enabled — unlike
# examples/vidda-mt9653/, which trades the voice UI for removing its second home screen.
# On this firmware that app raises no home-screen problem worth the loss.
#
# The active screensaver was the desk clock (com.google.android.deskclock), not the ad
# screensaver below; aerial's install.sh switches screensaver_components to Aerial's
# dream, so com.jamdeo.screensaver disables safely.
#
# Verified: applied in three batches (telemetry/push, ads/screensaver, factory leftovers)
# with a focus check between batches, then two cold reboots. Home, Wi-Fi, casting, IMEs,
# Bluetooth remote, voice, 聚好看 playback all checked the same day; not yet lived with
# for weeks.
#
# Second unit: Vidda C1 4K tri-colour laser projector (China), the same device MT9669, board
# m7642 and build PPR2.180905.006.A1 (02.02.60.02), VIDAA 6.6, 3.6 GB, ro.adb.secure=1.
# Nothing was disabled at the factory on this one. No Aerial: the active screensaver stayed
# the desk clock, so com.jamdeo.screensaver is not the dream either; the screensaver timeout
# was not waited out after disabling it. Two packages the C1S notes do not name were found
# and disabled (cloudfalcon, fusion.android.tv.demo, marked C1 below); the owner's own picks
# are the commented block at the end. Applied in six batches with a screenshot between them,
# then reboot-checked twice on 2026-11-01: every entry stayed disabled; Wi-Fi, the source
# panel and the Bluetooth remote kept working (casting was not tried), and free memory went
# from about 1.87 GB to 2.38 GB. The 双11 skin and side banner on 聚好看's home
# went with the ad services; its sponsored rows did not. Not yet lived with for days.

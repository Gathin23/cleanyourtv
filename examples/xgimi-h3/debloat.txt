# XGIMI H3 projector (model XK03E, device ironman, product Product_ys, reported model string
# "XGIMI TV"), GMUI (XGIMI's own UI, NOT Android TV), Android 8.0.0 (SDK 26), low-RAM build
# (ro.config.low_ram=true), build OPR5.170623.014 / v1.15.93 user dev-keys.
# CleanYourTV launcher applied on a real unit on 2026-10-31..11-02; every package below was disabled
# with `pm disable-user --user 0` (never uninstalled) and the unit was checked afterwards: launcher,
# GMUI settings service, Wi-Fi page, remote keys (incl. the Settings key) and the cast receiver all
# still work, no crashes in the drop box. Reboot-checked over a full power cycle: the 41 packages stay
# disabled, Home is still the default HOME, the cast receiver comes back on its own (~20 s).
# Note for anyone applying this list: `adb reboot` on this firmware powers the unit down instead of
# restarting it - it has to be woken with the remote, and it sleeps (and drops ADB) after a few idle
# minutes, so plan the checks around that.
#
# Status: verified on a real unit 2026-11-02 (Android 8.0, GMUI v1.15.93): launcher is Home, the
# disabled packages stay disabled across a full power cycle, GMUI settings service, the Wi-Fi page,
# remote keys (incl. the Settings key, keyCode 82) and the cast receiver all work; phone remote from
# the XGIMI mobile app works only while com.xgimi.mobilebridgeservice + com.xgimi.vcontrol stay enabled.
#
# Apply:   TV_HOST=<projector ip> tools/disable.sh examples/xgimi-h3/debloat.txt
# Undo:    TV_HOST=<projector ip> tools/restore.sh examples/xgimi-h3/debloat.txt
# Everything is DISABLED, not uninstalled. Comment out any line you want to keep.
#
# Stock launcher: com.xgimi.home (GMUI). NOT in this list: the launcher script disables it and
# restore.sh brings it back. Nothing else claims HOME on this firmware except the old boot wizard
# (disabled below) and CleanYourTV itself.
#
# ADB: this firmware ships ADB closed. Two ways in: System info page -> long-press LEFT on the remote
# opens the factory menu, ADB is on its second page; or install local.z7x.adb (kept enabled here on
# purpose - it is the enabler this unit was opened with; disabling it does not close the port once
# persist.service.adb.enable=1 / persist.adb.tcp.port=5555 are set, but it is the known-good way back
# in after a factory reset). Port 5555 over TCP.
#
# GMUI notes (needed by the CleanYourTV theme on this model):
# - Settings is a SERVICE, not an activity: action "XGimiSettingAction" on service
#   com.android.newsettings/com.xgimi.newsettings.SettingService with string extra "data" holding a
#   page URI (main, Settings://com.xgimi.settings.net/wifi, Settings://com.xgimi.settings.net/ap).
#   Reverse-engineered from /system/app/newsettings; used for the header gear, launcher settings,
#   quick panel and the remote Settings key.
# - The remote's Settings key is keyCode 82 (KEYCODE_MENU, scanCode 127), not 176.
# - The built-in cast receiver ("我的H3", DLNA/SSDP on :1718, com.xgimi.wirelessscreen) auto-downloads
#   云视听小电视 (com.gitvjimi.video) on first use; it and the content apps are disabled below.
#   Cast receiver is LeanCast (io.leancast, MIT, pure DLNA/UPnP MediaRenderer) instead: boot-autostart
#   foreground service, deviceidle-whitelisted. HPPlay 乐播投屏 (com.hpplay.happyplay.aw) is installed
#   but nothing starts it - only its .app.MainActivity fully initializes the SDK, broadcasts alone
#   leave an empty process, and its DaemonService dies within a minute on GMUI. Note the first
#   receiver tried, weekdayjast/MiracastReceiver, was removed again: it kept a Wi-Fi Direct
#   group up permanently, which is a hotspot mode on this single-MAC WiFi chip and starved the
#   wlan0 interface of multicast. Miracast itself stays impossible without root
#   (wifi_display_on=0, WFD IE needs signature-level CONFIGURE_WIFI_DISPLAY), so phones use the
#   cast button inside video apps (DLNA), which does work.

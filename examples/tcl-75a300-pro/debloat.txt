# Stock launcher: com.google.android.apps.tv.launcherx. Live TV / HDMI app: com.tcl.tv.
# Kept enabled on purpose: AirPlay (com.tcl.airplay2, com.mediatek.AirplayAPK, com.mediatek.airplaydaemon),
# TCL Live (com.tcl.channelplus), com.tcl.UpdatePeripheral (TCL soundbar), com.tcl.autopair, com.tcl.suspension,
# com.tcl.ttvs, com.tcl.tv, com.tcl.tvinput. See tcl-g08-eu-android12 for why autopair, suspension and ttvs stay.
#
# First set up with Claude Code and PROMPT.md, launcher installed 18 October 2026. On 31 October the launcher
# went from 2.0 to 3.2 (build-and-install.sh, SKIP_BUILD=1, over the old build) and the last five packages
# below were disabled with tools/disable.sh. After each of two reboots Home came back on the launcher (about
# 3 s of FallbackHome first) and all 40 stayed disabled; no launcher crashes in the crash log.
# android.autoinstalls.config.google.gtvpai was still enabled after the disable.sh run; a manual
# `pm disable-user --user 0` took.
#
# Remote (no key helper): YouTube, HDMI, volume, mute, Home and Back work and the soundbar connects. With
# launcherx off, Netflix (keycode 4062, scancode 566) and Settings (4077 / 561) did nothing: Settings logs
# "Start tcl set short press" and then nothing resolves TOGGLE_NOTIFICATION_HANDLER_PANEL (launcherx handled it).
# Fix: app_keys "4062:com.netflix.ninja" and "4077:settings" with INPUT_KEY_SERVICE=1. Checked on the real
# remote, and a held volume button still ramps normally here with the helper on. YouTube sends 4065 / 569.
# show_stats shows memory and storage but no CPU figure on this set.

# manufacturer SkyworthDigital, device YYT, product HP4609-Skyworth, Amlogic (ro.board.platform HP46B),
# about 1.9 GB RAM. Google TV 14 (API 34), build UKG3.260128.001.C3.3.5_20260723.
# Tested in Australia; second unit on the same firmware build and 32-bit userspace (armeabi-v7a)
# tested in Mexico and lived with for five days across multiple reboots.

# Apply:   TV_HOST=<tv ip> tools/disable.sh examples/wanbo-x5-pro/debloat.txt

# Everything is DISABLED, not uninstalled. Comment out any line you want to keep.
#
# Applied on 2026-10-19 (first unit, v2.3 launcher) and 2026-10-21..2026-10-26 (second unit, five days
# of daily use across cold reboots): Home, D-pad navigation, launching apps from the dock, Bluetooth
# audio, projector autofocus/keystone and casting all verified. Nothing re-enabled itself after reboot.
#
# Stock launcher: com.google.android.apps.tv.launcherx. setupwraith .RecoveryActivity also claims HOME
# (priority 1): with only launcherx disabled, Home went to it and it restarted itself every ~60 ms.
# Disabling just that component is refused (SecurityException), so the whole package is in this list.
# No tuner and no HDMI inputs on the stick, so no live_tv_package; the launcher hides its Inputs pill.
# Disabled from the factory, so not listed: com.google.android.tv.axel.
#
# Quirks on this firmware, all checked on the device:
# - USB debugging opened port 5555 without pairing. After a reboot it was closed again until
#   debugging was toggled back on (Wireless debugging also offers a random port with pairing).
# - The Wi-Fi network had been saved during first setup, so disabling setupwraith deleted it and the
#   projector dropped off the network mid-command. Rejoining from the projector's own Wi-Fi settings
#   fixed it, and the network then belonged to android.uid.system. Check first:
#   `dumpsys wifi | grep -o 'cname=[^ ]*'`.
# - `adb install` over Wi-Fi hung; most likely Play Protect's prompt was waiting behind the screensaver.
#   Pushing the APK as base64 chunks and running `pm install` worked. Wake the screen before installing.
# - com.android.devicelockcontroller is protected: `pm disable-user` is refused.
# - Second unit (remote buttons): `com.sdt.globalkey` routes the remote's four app buttons and Settings
#   gear to launcherx. Once launcherx is disabled, the Settings gear emits KEYCODE_NOTIFICATION (83) and
#   the four app buttons emit KEYCODE_STEM_1 (265, Netflix), KEYCODE_STEM_2 (266, YouTube),
#   KEYCODE_F8 (138, Prime Video) and KEYCODE_F6 (136, Disney+). Enabling HOME_KEY_SERVICE=1 and
#   INPUT_KEY_SERVICE=1 with `settings_key_keycodes` `[83]` and `app_keys` for `265`, `266`, `138` and
#   `136` restores all five buttons. The projector's physical autofocus and keystone buttons are handled
#   by `com.sdt.projector.observer` and keep working without launcherx.
#
# Kept on purpose: com.sdt.projector.observer (projector accessibility service, autofocus and keystone),
# com.mft.rcupair (remote pairing), com.sdt.globalkey (remote hot keys), com.mft.frontpanelledsservice,
# com.google.android.tv.dfuservice (remote firmware and backlight), com.droidlogic.* (Amlogic settings
# and connected devices), com.dolby.android.audio.service, the keyboard, Play Store, Play Services.

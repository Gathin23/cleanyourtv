# Second unit, North American firmware: build BRAVIA_VH2_M_UC-user 12 STT2.230505.001.S136 682241,
# same board and the same build number as the EU unit above. Every package in this list is present and
# every one disabled cleanly, but two things differ:
#
#  - Home handover needs the stock launcher disabled. On this firmware launcherx registers its HOME
#    intent filter at priority=2, which outranks the preference `cmd package set-home-activity` writes:
#    it prints Success while `resolve-activity` keeps naming launcherx. Disabling setupwraith alone did
#    not hand Home over either, so the note above about leaving launcherx enabled does not hold here.
#    Disabling it (the commented line at the end of this list) handed Home over at once, and the TV has
#    booted to the new launcher since. Check with `dumpsys activity activities | grep mFocusedApp`, not
#    with the "Success" from set-home-activity.
#  - promos, seeds.iot and b2b.vendorprotocol ship ENABLED here, where the EU unit has them off at the
#    factory; sonyselect and seeds.iot.remotestart are enabled too and were not named either way above.
#    They are in the list below, so one file covers both regions: on an EU set they are already disabled
#    and recovery.py records that, so undo leaves them alone.
#
# The Input-button service was NOT needed on this unit: with launcherx disabled, the remote's Input,
# gear and app buttons were all still answered by Sony's own firmware (checked on the real remote, not
# with injected keys), so INPUT_KEY_SERVICE was left off and key auto-repeat kept. On Ethernet, so the
# setupwraith Wi-Fi check did not apply. Applied over one evening, not lived with for days.
#

#  - It carries extra preloads the list above didn't cover: Sony's tab, partner auto-installs, usage
#    agents and India-market streaming apps. They are in the "Asia-Pacific unit" groups below; on a set

# Everything is DISABLED, not uninstalled. Comment out any line you want to keep.

# Tested on: the owner's own unit, one session, reported in #3794. The eleven packages below were
# disabled, setupwraith and launcherx among them for the Home handover, and the owner reports the
# launcher installed and running on that firmware with the apps they kept still working. That is one
# session, not the multi-day soak this folder's BenQ list has: no reboot, HDMI or tuner playback,
# casting or standby/wake check was reported, so read the list back with `pm list packages -d` after a
# reboot before you rely on it.
#
# Quirks on this firmware, as the owner found them (#3794), the first two the same as this folder's
# BenQ list:
# - USB debugging alone opens port 5555; there is no separate Wireless debugging toggle.
# - HOME candidates: setupwraith at priority 1 above launcherx at priority 2, so setupwraith is
#   disabled first and the launcher installed after it.
#   Disabling setupwraith gives Home back but costs casting (Chromecast built-in); keep it enabled if you cast to this TV.
# - The saved Wi-Fi network was owned by android.uid.system, not setupwraith
#   (`dumpsys wifi | grep -o 'cname=[^ ]*'`), so disabling setupwraith left the network in place. That
#   is not true of every DVB96 unit: examples/tuvio-td43ufbcv5 found setupwraith owning it and had to
#   forget and re-join the network first. Check the cname on your own set.
# - The default screensaver is dreamx's Backdrop. Point it at the launcher's clock before disabling
#   dreamx:
#   settings put secure screensaver_components com.gathin.tvhome/.ClockDream
#   tools/restore.sh does not undo it. The BenQ list beside this one also sets
#   screensaver_default_component; the Impex owner set screensaver_components only.

# ro.product.manufacturer=skyworth, device SW4H, API 29, armeabi-v7a, ~1.68 GB RAM.
# Stock launcher: com.google.android.tvlauncher (classic Android TV home, not Google TV launcherx).
# Live TV: com.smartdevice.livetv / com.mediatek.tvinput.

# Apply:   TV_HOST=<tv ip> tools/disable.sh examples/karbonn-swtv-20ae/debloat.txt
# Undo:    TV_HOST=<tv ip> tools/restore.sh examples/karbonn-swtv-20ae/debloat.txt com.google.android.tvlauncher
# Everything is DISABLED, not uninstalled. Comment out any line you want to keep.
#
# Tested on the day of debloat and confirmed working. Same Skyworth SW4H platform as the
# Panasonic 4KTV-0SU and OnePlus Y1. com.sky.market is a protected package: the firmware
# refuses pm disable-user for it (SecurityException); it stays on.
#
# Performance tweaks for 1.68 GB RAM (32-bit armeabi-v7a, MediaTek):
#   settings put global window_animation_scale 0.5
#   settings put global transition_animation_scale 0.5
#   settings put global animator_duration_scale 0.5
#   settings put global background_process_limit 2
# Set reduced_motion: true in your theme's config.json for the CleanYourTV launcher.
#
# Unit 2 (Motorola SWTV-20AE), applied 2026-10-23 in batches with a screenshot after each, then the
# CleanYourTV launcher with HomeKeyService; Home, helpers and every disable held over two reboots.
# Seen on that unit:
# - com.google.android.tvrecommendations froze system_server's main thread for 2 s every 32 s
#   (logcat: "Slow dispatch took 2002ms ... AlarmManager", just before its ForegroundActivityTrackerJobService).
#   While HomeKeyService filters keys, a key release that lands in that freeze makes Android auto-repeat, so
#   the D-pad "keeps moving". Disabling it (already in this list) made the freezes rare.
# - The firmware puts the screensaver back to Google Backdrop at boot (ScreenSaverSetDefTimeReceiver). To keep
#   the launcher's clock, set both `settings put secure screensaver_components com.gathin.tvhome/.ClockDream`
#   and `screensaver_default_component` to the same value.
# - With HomeKeyService filtering keys, a held volume key steps only once: Android 10 applies the step before
#   the helper sees the key. key_filter false brings hold-to-ramp back, at the cost of the remote buttons.
# - Remote buttons handled by HomeKeyService ignore keys sent with `input keyevent`; test them with the remote.
# - Granting usage access with appops is lost if the TV reboots before Android saves it: run
#   `cmd appops write-settings` straight after.
# - A saved Wi-Fi network joined in the first-run wizard belongs to setupwraith and is forgotten when it is
#   disabled (`dumpsys wifi | grep -o 'cname=[^ ]*'`). The home network there was android.uid.system.
#
# Unit 3 (Thomson, SPPL), applied 2026-11-08 in four batches with a screenshot after each, then the CleanYourTV
# launcher; every disable, Home and the ClockDream screensaver held over a reboot. Seen on that unit:
# - com.sky.market and com.smartdevice.tvworkwithalexa were already disabled when it arrived; with the latter
#   off, HDMI inputs and Live TV still switched from the launcher's Inputs menu on this unit.
# - setupwraith does not claim HOME here and the saved Wi-Fi network was android.uid.system, so it stays on.
# - The remote is "TV BLE Remote". Input (keycode 178) opens Skyworth's own input menu and the mic (219) opens
#   the Assistant with no key helper, and a held volume key ramps. One app button sends keycode 188
#   (KEYCODE_BUTTON_1, scancode 397) and does nothing once the stock launcher is off; `app_keys` with
#   INPUT_KEY_SERVICE=1 maps it, at the cost of hold-to-ramp volume (see Unit 2).
# - A reboot sent over ADB leaves the set in standby with Wi-Fi off; press Power once and it is back in ~1 min.
# - Lived with from 2026-11-08 to 2026-11-12 (4 days of daily use), including the "Also disabled on Unit 3" group.

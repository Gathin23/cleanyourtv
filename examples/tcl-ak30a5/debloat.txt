# TCL ak30a5 — Chinese-market TCL Android TV 9, Amlogic SoC
# Android 9 (PPR1.180610.011), locale zh-CN, NO Google services at all
# (0 com.google.* packages, no Play Store — apps come from com.tcl.appmarket2 or a USB stick).
# Likely a good starting point for other 2020-2023 Chinese TCL sets on the same Amlogic firmware.
#
# TWO UNITS, TWO FIRMWARE GENERATIONS — read the build date before you use a line:
#
#   1) TCL ak30a5, build date 20230208, 1.5 GB RAM. The original list; its entries are unchanged.
#   2) TCL 雷鸟雀4 55F270C-JN (2025 model), build date 20250610, 2 GB RAM, fingerprint
#      TCL/ak30a5/ak30a5:9/PPR1.180610.011/20250610:user/dev-keys, China (zh-CN).
#      Same board, same Android version, newer firmware. Lines marked "20250610" were only
#      verified on that unit. It ran this list for three days, with the Home handover, the
#      accessibility guard and the boot behaviour re-checked after several reboots.
#   3) TCL ak30a5, build date 20250401, fingerprint TCL/ak30a5/ak30a5:9/PPR1.180610.011/20250401,
#      zh-CN. Status: one evening (2026-10-27) with two reboots — NOT the several days this list
#      asks for, so treat the 20250401 notes below as unverified for daily use. Nothing in the
#      package list itself was changed for this unit.
#      Differences measured on that unit:
#      - Network ADB survives reboots on this build (unlike 20250610): port 5555 answered again
#        after both reboots without re-enabling anything.
#      - `pm install` reaches PackageManager and the verifier is what refuses sideloads
#        (INSTALL_FAILED_VERIFICATION_FAILURE), like 20250610 — but `settings get global
#        verifier_verify_adb_installs` is 1 here, not null. Both verifier settings to 0 and
#        `pm install -r` succeeds. Restore both to 1 afterwards.
#      - A third-party launcher CAN be installed and can own Home on this generation, contrary to
#        the 20230208 note below: com.gathin.tvhome (this repo's launcher) installed with the
#        verifier off, `cmd package set-home-activity` worked, and Home survived two reboots with
#        com.tcl.cyberui disabled. In the launcher's config: live_tv_package com.tcl.tv plus
#        live_tv_action android.intent.action.MAIN (com.tcl.tv has no leanback launcher activity
#        on this build either; the action opens its .TVActivity directly).
#      - Disabling com.tcl.cyberui has a quirk: its old task can still be brought to the front
#        once in a while within the same boot (logcat shows am_on_start_called for the disabled
#        package). It stays dead across a reboot; pressing Home after a re-assert of
#        set-home-activity fixes the session.
#
# Apply:   TV_HOST=<tv ip> tools/disable.sh examples/tcl-ak30a5/debloat.txt
# Undo:    TV_HOST=<tv ip> tools/restore.sh examples/tcl-ak30a5/debloat.txt com.tcl.cyberui
# Everything is DISABLED, not uninstalled. Comment out any line you want to keep.
#
# Stock launcher: com.tcl.cyberui. On 20230208 it is a PERSISTENT priv-app; on 20250610 it is a
#   SYSTEM app with UPDATED_SYSTEM_APP (an update in /data/app over /system/priv-app), versionCode
#   7748, and WITHOUT the PERSISTENT flag. See the note below before disabling it.
# Live TV / HDMI: com.tcl.tv. There is NO standard TvInputManager on this firmware (`service list`
#   has no tv_input), so the launcher's Inputs menu opens TCL's own source panel instead:
#   startService(com.tcl.settings/com.tcl.insrc.ShowWindowService, action com.tcl.insrc.SHOW_WINDOW).
#   Keep com.tcl.settings or that panel is gone. HDMI source ids: TV=2, AV1=3, HDMI1=8, HDMI2=9.
#   That panel is a service, not an activity: `cmd package resolve-activity -a
#   com.tcl.insrc.SHOW_WINDOW` answers "No activity found", so use `am start-service`.
# Keep com.tcl.tv: it owns DTV/HDMI playback and the remote's source key (KEYCODE_TV_INPUT still
#   opens the source panel over any launcher, cyberui or not).
# Keep com.sohu.inputmethod.sogou.tv: it is the ONLY input method on the TV. Disable it and there is
#   no on-screen keyboard at all.
# Keep com.tcl.guard: 电视卫士 is also the only on-screen APK installer (应用安装, needs a USB stick).
# Keep com.tcl.ui_mediaCenter if you play anything from USB.
# Keep com.tcl.appmarket2 and com.tcl.versionUpdateApp: on 20250610 the boot package was
#   com.tcl.appmarket2, and the OTA updater is worth keeping.
#
# Known quirks on the 20230208 firmware:
# - `pm install` is patched to refuse shell installs ("install apk has be disabled from pm by
#   system default"), and PackageInstallerActivity is exported=false with its intent filters removed.
#   `pm install-commit` is not gated though: an APK can still be installed by creating a
#   PackageInstaller session from a shell-run app_process and committing that session.
# - APKs that declare android.intent.category.HOME are refused at parse time unless they are signed
#   with TCL's key: "INSTALL_PARSE_FAILED_INCONSISTENT_CERTIFICATES: disable install launcher app not
#   signature by tcl". A third-party launcher therefore cannot be installed on this model at all;
#   com.tcl.cyberui stays and only its ad/telemetry packages (this list) can be removed.
# - 电视卫士 → 应用安装, the only on-screen installer, stages the APK as a file without the .apk
#   suffix and fails with INSTALL_PARSE_FAILED_NOT_APK ("Failed to parse .../my_app_session") for
#   every package. Don't use it.
# - Installs also need roughly 600 MB free on /data or they fail with
#   INSTALL_FAILED_INSUFFICIENT_STORAGE; `pm trim-caches 2000M` is usually enough.
# - Installed launcher version here is com.tcl.cyberui 7746 (7.7.46). The 灵控桌面 APKs circulating
#   for TCL sets are the same package at versionCode 7670 (7.6.70), i.e. a downgrade.
# - screensaver_components ships pointing at com.android.deskclock, which is not installed, so the
#   TV has no working screensaver out of the box (and launcher/'s Clock can't be installed here).
# - /data/local/tmp is not writable by the shell user; push to /sdcard instead.
# - `screencap` cannot write to /data/local/tmp either, and returns an empty file while Live TV/HDMI
#   is on screen (same as the G10). Press Home first.
# - No com.android.dreams.basic fallback screensaver. Also no TCL equivalent of `pm install`.
#
# What is different on the 20250610 firmware (all measured on that unit, 2026-10-22 to 2026-10-25):
# - `pm install` is NOT patched any more. With no argument it answers "Failed to parse APK file:
#   null" — it reaches PackageManager. What refuses the APK is the verifier in front of `pm
#   install` (INSTALL_FAILED_VERIFICATION_FAILURE), not the parse-time signing gate above, and
#   `settings get global verifier_verify_adb_installs` is null.
# - /data/local/tmp IS writable by the shell user. The narrower quirk: rename(2) is refused there,
#   so `mv` answers "bad '/data/local/tmp/x': Permission denied" while `cp` and `> file` work. Use
#   `cp`, not `mv`, when placing a file for tools/b64push.py, which verifies an md5 before it puts
#   the file in place.
# - The stock launcher is versionCode 7748 (7.7.48) there, not 7746.
# - The firmware turns USB debugging back off on every reboot: service.adb.tcp.port is still 5555
#   but nothing listens and `adb connect` answers "connection refused". It has to be re-enabled by
#   hand on the TV each time (设置 → 本机信息 → remote-control "上上下下左右", or 信源 → 模拟接收
#   → 菜单 → 对比度 → 输入 1950). Any scripted run that spans a reboot needs that manual step.
#

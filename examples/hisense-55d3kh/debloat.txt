# Hisense 55D3KH (China market), JuUI on Android 11
#   ro.product.model           = VIDAA_TV
#   ro.product.hisense.model   = 55D3KH
#   ro.product.device          = MT9603
#   ro.product.board           = D3K
#   ro.build.version.release   = 11  (API 30)
#   ro.build.display.id        = RP1A.200720.011 release-keys
#   ro.build.description       = D3K-user 11 RP1A.200720.011 02.02.70.20250214160513 release-keys
#   ro.adb.secure              = 0     <- no "Allow USB debugging?" prompt, see below
#   service.adb.tcp.port       = 5555
#
# Same JuUI namespace as examples/hisense-65d62qh/, examples/hisense-e5q-pro/ and
# examples/vidda-mt9653/ (com.jamdeo.* / com.hisense.*), but this set is device MT9603 (board D3K,
# armv7, 1.9 GB) on the 02.02.70 build line, so the list was derived from those and then re-checked
# package by package against this set's own `pm list packages` (107 packages). Packages those lists
# name that are not installed here are left out rather than copied over.
#
# ADB: turning USB debugging on opens port 5555 directly, and ro.adb.secure=0 means the TV never shows
# the "Allow USB debugging?" dialog: ANY device on the LAN gets a shell with no prompt. Close the
# debugging switch when the work is done and confirm the port really refuses connections
# (tools/adb-closed.py <tv ip>).
#
# State at the time this list was written (2026-11-28):
#   pm list packages -d        -> com.android.bluetooth only, disabled at the factory; left alone.
#   No Google services: no com.google.android.*, no Play Store, no leanback launcher. The account and
#   store layer is JuUI (com.hisense.hitv.*, com.jamdeo.tv.vod).
#   No browser and no webview-based launcher: the browser lane that other VIDAA lists use does not
#   exist here, so a launcher swap has to be a native APK plus the vendor properties below.
#
# Applied on the real set on 2026-11-28: five batches, each followed by a cold reboot, with the input
# panel, the remote, Wi-Fi/Ethernet and the app library checked after every one. 38 packages stick.
# com.jamdeo.updateservice is disabled on the owner's instruction (see BATCH 5), which is a departure
# from the repo's default of leaving the OTA updater enabled.
#
# Read before applying:
#   * This list does NOT change how Home looks. The sponsored rows, the VIP banner and the promo tiles
#     are fetched by com.jamdeo.tv.vod itself, not by the ad sidecars below. Only swapping the launcher
#     removes them. What this list buys is the telemetry, the push channel, the persistent network
#     poller, the ad SDK processes and the leftover preloads.
#   * Everything is DISABLED (pm disable-user --user 0), never uninstalled. tools\disable.ps1 records
#     each package's original state under %USERPROFILE%\.cleanyourtv\ before touching it, so
#     tools\restore.ps1 with this same file puts it all back.
#   * Apply in batches, reboot after each one, and confirm the TV boots, the remote works, the source
#     panel switches to HDMI and the network is still up. A batch can take something load-bearing with
#     it and you cannot tell which without the reboot. `adb shell sync` plus about 20 seconds before
#     rebooting matters: Android writes package state to disk late, and a reboot sent straight after a
#     batch boots with the old state and reads as if the firmware re-enabled everything.
#
# Apply:   tools\disable.ps1 -TvHost <tv ip> examples\hisense-55d3kh\debloat.txt
# Undo:    tools\restore.ps1 -TvHost <tv ip> examples\hisense-55d3kh\debloat.txt
# Reboot:  & tools\venv\Scripts\python.exe -I tools/tv.py --reboot   # returns once ADB accepts it; wait for the TV to come back
# Compare: & tools\venv\Scripts\python.exe -I tools/tv.py 'pm list packages -d'
# Comment out any line you want to keep.

# HOME: this list is debloat only; the stock Home stays. Replacing Home on this set does not need root
# but does need the vendor's own properties, not the HOME role:
#   adb shell setprop persist.vt.use_home_pkg <launcher package>
#   adb shell setprop persist.sys.boot.source_pkg <launcher package>
# Both are empty at the factory and both are what make the Home key and power-on open the new
# launcher. The accessibility Home Guard route does not work here: this firmware reports
# InputFilterEnabled: false, so a guard service cannot filter the key.

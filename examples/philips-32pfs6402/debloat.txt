# Philips 32PFS6402/12 (TP Vision QM164E, device QM16XE_F, board 2K16EU1, MediaTek MT5861), France
# Android TV 7.1.2 (API 25), build N2G48H, firmware QM164E.0.16.102.24, security patch 2018-08-05.
# Fingerprint: PHILIPS/QM16XE_F/QM16XE_F:7.1.2/N2G48H/01610224:user/release-keys
# 1.6 GB RAM, Wi-Fi. Same 2016 TP Vision platform as examples/philips-49pus6561 (QM163E, QM16XE_U), but this
# FHD set stayed on Android 7.1.2; entries shared with that list were checked against this TV's `pm list packages`.
#
# Apply:   $env:TV_HOST="<tv ip>"; tools\disable.ps1  examples\philips-32pfs6402\debloat.txt   (Windows)
#          TV_HOST=<tv ip> tools/disable.sh  examples/philips-32pfs6402/debloat.txt            (macOS/Linux)
# Undo:    $env:TV_HOST="<tv ip>"; tools\restore.ps1 examples\philips-32pfs6402\debloat.txt   (Windows)
#          TV_HOST=<tv ip> tools/restore.sh  examples/philips-32pfs6402/debloat.txt            (macOS/Linux)
# Everything is DISABLED, not uninstalled. Comment out any line you want to keep.
#
# TVINPUT_ALLOW=1: without it disable.sh skips org.droidtv.usagelogger and org.droidtv.demome (both ask for
# TV_INPUT_HARDWARE). Neither serves an input: the hardware inputs come from org.droidtv.tunerservice,
# hdmiService (HDMI 1-4), scartService and componentService only. Apply the list without the override first,
# reboot, check Live TV and your inputs, then run it again with TVINPUT_ALLOW=1.
#
# Stock launcher: com.google.android.leanbacklauncher. It is NOT in this list: the launcher half needs Android 8
#                 (minSdk 26) and this set is API 25, so the stock home stays. Home also answers the fallback
#                 com.android.tv.settings/.system.FallbackHome.
# Live TV app:    org.droidtv.zapster (the TV powers on to Live TV).
# Screenshots:    `screencap` returns 0 bytes on every screen of this firmware, Settings included; check with
#                 `dumpsys activity activities | grep mResumedActivity` and the real screen instead.
# Private DNS:    not available (Android 9 and newer only).
#
# ADB: USB debugging alone opens TCP 5555, with the RSA prompt (ro.adb.secure=1). Port 5555 stays OPEN after
# turning USB debugging and Developer options off, revoking the authorisations, `settings put global
# adb_enabled 0` (it still read 1 with the switch shown off) and a mains power cycle: tools/adb-closed.py
# still reports it open after boot. With no key authorised, a connection only gets the on-screen prompt.
# See README.md.
#
# Kept on purpose, do NOT disable: org.droidtv.zapster, org.droidtv.tunerservice, org.droidtv.hdmiService,
# org.droidtv.scartService, org.droidtv.componentService, org.droidtv.xtv, org.droidtv.tvserver,
# org.droidtv.GlobalKey (remote buttons), com.mediatek.autopair (remote pairing), org.droidtv.settings,
# org.droidtv.tvsystemui, org.droidtv.nettvbrowser (HbbTV), org.droidtv.eum, org.droidtv.contentexplorer
# (USB media player), org.droidtv.dlna, org.droidtv.oad (firmware updates), org.droidtv.alhuewizard and
# org.droidtv.ambihuecommon, org.droidtv.icp (asks for TV_INPUT_HARDWARE, purpose unclear), org.droidtv.tv.upg,
# com.google.android.apps.mediashell (Chromecast), com.google.android.tv.remote.service, Play Store and Play
# Services. Factory packages (org.droidtv.factory*, org.droidtv.factimageview, org.droidtv.factthreed) were
# not opened and are left alone.
#
# Status: 2026-11-11, applied in six batches with two reboots; every entry stayed disabled across both, none

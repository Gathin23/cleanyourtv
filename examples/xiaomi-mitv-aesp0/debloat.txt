# Xiaomi MiTV-AESP0 (codename aquaman), Android TV 9 (SDK 28), firmware PI.2055.
# Stock launcher: com.google.android.tvlauncher (disabled by launcher/build-and-install.sh).
# Live TV app: none (no tuner/HDMI inputs); com.google.android.tv is Live Channels.
#
# Apply:   TV_HOST=<tv ip> tools/disable.sh examples/xiaomi-mitv-aesp0/debloat.txt
# Undo:    TV_HOST=<tv ip> tools/restore.sh examples/xiaomi-mitv-aesp0/debloat.txt
# Everything is DISABLED, not uninstalled. Comment out any line you want to keep.
#
# Before applying:
# - com.xiaomi.android.tvsetup.partnercustomizer is commented out: on many Xiaomi sets it handles Bluetooth
#   remote pairing and the remote's shortcut buttons. Uncomment it only if you never re-pair the remote.
# - com.google.android.tungsten.setupwraith stays in the list, but tools/disable.sh skips it while it owns the
#   saved Wi-Fi network (see the fourth set). Disabling it costs casting, so comment it out to keep Chromecast.
#
# Notes from this firmware:
# - Default IME is already Gboard, so the Mi TV 4A missing-keyboard quirk doesn't apply.
# - The remote's Home button sends KEYCODE_ALL_APPS (284), not HOME. Android 9 sends that key only
#   to the system launcher, so with tvlauncher disabled Home does nothing. Fix: install with
#     HOME_KEY_SERVICE=1 TV_HOST=<tv ip> launcher/build-and-install.sh
#   which enables the launcher's HomeKeyService. Android switches it off on every reinstall,
#   so always pass HOME_KEY_SERVICE=1.
#   `input keyevent 284` over adb skips the accessibility filter; test with the real remote.
# - No HDMI/AV inputs: the launcher hides its Inputs pill by itself on this stick.
# - Kept on this set: voice assistant (katniss/pumpkin), Chromecast (mediashell; casting also needs
#   setupwraith, which the list disables),
#   Mi Cast (com.mitv.milinkservice) and firmware updates (com.xiaomi.mitv.updateservice).
# - After the last batch, wait about 40 s before rebooting (see the fourth set): with a shorter wait the
#   last packages disabled can come back enabled after the reboot. Check with `adb shell pm list packages -d`.
#
# Second verified set (Indonesia-region unit, same firmware PI.2055, in daily use since
# 21 Oct 2026 with Netflix / Jellyfin / SmartTube / Vidio): the groups marked
# "second set" below are disabled on that stick on top of the original list, including
# partnercustomizer (now commented out by default, see above).
# Region note: the ID unit has only the misspelled autoinstalls package below, and
# none of the preloaded apps in the original list (DAZN, Red Bull TV, Duo, TCL browser).
#
# Third verified set (France unit, same firmware PI.2055, patch 2022-08-05, debloated 21 Oct 2026; the group
# marked "third set" below is on top of the original list, plus voice, Chromecast, Mi Cast, the phone remote and
# the updater off by the owner's choice). Notes from that unit:
# - The Home key arrived as KEYCODE_HOME (3), not ALL_APPS: `interceptKeyTq keycode=3` in logcat, then HOME
#   started the launcher. HOME_KEY_SERVICE=1 was used anyway and does no harm; check your remote's revision.
# - The Netflix key is Xiaomi keycode 1001, consumed by the system in interceptKeyBeforeQueueing without
#   POLICY_FLAG_PASS_TO_USER, which launches Netflix itself. Accessibility services never see it, so it cannot
#   be remapped (app_keys, Button Mapper) without root; with Netflix disabled the key just does nothing.
# - Closing ADB: switching off "USB debugging" alone, then rebooting, left 5555 open. Switching off the
#   Developer options master switch and rebooting closed it (tools/adb-closed.py: refused).
# - Free memory: about 150 MB stock, about 265 MB right after a reboot with the list and the launcher.
#
# Fourth verified set (Peru unit, older firmware PI.1241, debloated 29 Oct 2026 with the launcher, HOME_KEY_SERVICE=1
# and a dock of Netflix / YouTube / Disney+ / Prime Video). Every line below that was uncommented at the time and that
# this firmware has was disabled (partnercustomizer included), except setupwraith; voice, Mi Cast and the updater
# stayed enabled, and so did Chromecast. Notes from that unit:
# - setupwraith owned the saved Wi-Fi network (`dumpsys wifi | grep -o 'cname=[^ ]*'` showed
#   cname=com.google.android.tungsten.setupwraith), so it stayed enabled: disabling it would have taken the stick off
#   Wi-Fi and ADB. tools/disable.sh checks this and skips setupwraith by itself. Keeping it is also why
#   casting kept working on that unit.
# - Not installed on PI.1241: android.autoinstalls.config.xiaomi.mibox3 (only the "xioami" one is), com.dazn, Red Bull TV,
#   Duo, the TCL browser, com.mitv.tvhome.atv, com.mitv.download.service, com.mitv.videoplayer, com.xm.webcontent and
#   Alphonso. tools/disable.sh reports those lines and goes on.
# - After the last batch, `sync` and a 15 s wait were not enough: after the reboot the last eight packages
#   were enabled again. Disabling them again and waiting about 40 s before the reboot kept all of them.
# - The real Home button returned to the launcher with HOME_KEY_SERVICE=1.
# - Closing ADB: revoking the USB debugging authorisations, switching off the Developer options master switch and
#   rebooting closed 5555 (tools/adb-closed.py: refused), as on the third set.

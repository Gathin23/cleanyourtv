# Cecotec VQU10065S (65" QLED, product no. 02605, Vestel-built in Turkiye, codename "shandao"),
# Android 14 (API 34), firmware UKNV.260304.001, 1.8 GB RAM, MediaTek platform.
# ro.product.manufacturer = vestel, ro.product.model = "Android TV".
# UK-market firmware: every uk.co.freeview.* package already ships disabled.
#
# Apply:   TV_HOST=<tv ip> tools/disable.sh examples/cecotec-shandao/debloat.txt
# Undo:    TV_HOST=<tv ip> tools/restore.sh examples/cecotec-shandao/debloat.txt
# Everything is DISABLED, not uninstalled. Comment out any line you want to keep.
#
# Stock launcher: com.google.android.tvlauncher (the scripts' default, not Google TV launcherx).
# Only com.android.tv.settings/.system.FallbackHome also claims HOME.
#
# KEEP, even though the names look like bloat:
# - com.mediatek.android.leanbacklauncher.partnercustomizer: provides the tvlauncher.widget provider.
#   Disabling it crash-loops com.mediatek.tv.service after a reboot on MediaTek sets and kills the
#   Input key and other remote hotkeys (see examples/chiq-ai-pont). Left enabled here.
# - com.google.android.tungsten.setupwraith: may own the saved Wi-Fi network; disabling it deletes
#   the network and takes the TV off Wi-Fi and ADB.
# - com.mediatek.tv.service, com.mediatek.tvinput, com.mediatek.wwtv.tvcenter (Live TV and the
#   source menu), com.mediatek.autopair (Bluetooth remote pairing).
#   com.mediatek.wwtv.mediaplayer was in this KEEP list and has moved to the disable list below:
#   it is the USB media player, not an input driver. tools/disable.sh still skips it, because it
#   asks for TV_INPUT_HARDWARE and the guard reads that as the HDMI/AV/tuner layer. On this set
#   that is a false positive: the permission is requested, nothing implements a TvInputService.
#   What settles it is which packages actually serve that service:
#     pm query-services --components -a android.media.tv.TvInputService
#   Here that lists only com.mediatek.tvinput (tuner, HDMI, VGA, composite, component, SCART) and
#   com.mediatek.tv.service, both kept. Disabled by hand and reboot-tested: all seven inputs and
#   the source panel still work. Use TVINPUT_ALLOW=1 to disable it, and check your own inputs
#   after a reboot before trusting this on another model.
# - com.vestel.tv.service, com.vestel.tv.keycontroller (remote keys), com.vestel.tv.backlight,
#   com.vestel.tv.eib (the E-User Manual app).
# - com.android.devicelockcontroller is a PROTECTED package on this firmware: pm refuses it with
#   SecurityException "Cannot disable a protected package". Not in the list.
# - com.dolby.android.audio.service, com.android.tv.settings, com.android.vending,
#   com.google.android.gms, com.google.android.gsf, com.google.android.inputmethod.latin.
#
# Owner's choices: Netflix, Prime Video, Spotify, Twitch, YouTube and Chromecast built-in
# all stay enabled. The Coocaa AirPlay app is off by choice. io.github.jqssun.airplay (the repo
# README's AirPlay answer) installs and runs correctly on this hardware: it registers
# _airplay._tcp and _raop._tcp through NsdManager and listens on 7000. It is useless on a managed
# network that isolates clients, though, because mDNS never reaches the other devices. Check with
# `arp -n <tv ip>`: a placeholder MAC means proxy ARP and no AirPlay discovery, whatever you install.

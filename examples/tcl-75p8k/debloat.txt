# Known quirks on this firmware:
# - Developer options has no separate Wireless/Network debugging toggle, but switching USB debugging ON
#   opens network ADB on TCP port 5555 over Wi-Fi directly.
# - `cmd package set-home-activity` prints Success, but launcherx keeps Home until it is disabled; then
#   com.google.android.tungsten.setupwraith (`RecoveryActivity`) claims Home until setupwraith is disabled too.
# - The Wi-Fi network saved during first-time setup belongs to setupwraith (`dumpsys wifi | grep -o 'cname=[^ ]*'`).
#   Forget the network and re-join it in Settings > Network & Internet BEFORE disabling setupwraith (so the network
#   is owned by com.android.tv.settings), or Android will delete the saved Wi-Fi network when setupwraith is disabled.
# - com.tcl.suspension is TCL's Input/source picker (`VIEW_INPUTS`), not an ad overlay: keep it enabled.
# - HDMI 1 is `com.tcl.tvinput/.passthroughinput.TvPassThroughService/HW15` (with HDMI-CEC child inputs under it).
# - On the 55" unit the saved Wi-Fi already belonged to android.uid.system, so setupwraith did not own it there.
# - tools/disable.sh skips android.autoinstalls.config.google.gtvpai, com.android.wallpaperbackup, waipu.tv and
#   Joyn here: their dumpsys has no permission block, so the input-driver check cannot read them. Only
#   com.tcl.tvinput serves TvInputService (`pm query-services --components -a android.media.tv.TvInputService`);
#   once HDMI works after a reboot, TVINPUT_ALLOW=1 disables them.
# - To keep casting, the 55" unit kept setupwraith and launcherx and took Home with stock_home_redirect
#   (key_filter false, HomeKeyService only, as in tcl-q7c-google-tv/). Remote buttons, HDMI and the volume ramp all
#   worked, but after a cold boot the TV stays on Google TV's home until Home is pressed once (#1546).

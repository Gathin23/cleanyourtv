# as the G05 (Quick Panel, waterfall, ttvs, TCL Live) plus the 43C645 extras (useragreement, TCL webview,
# tclhome_passive).
#
# Apply:   TV_HOST=<tv ip> tools/disable.sh examples/tcl-g07-google-tv/debloat.txt
# Undo:    TV_HOST=<tv ip> tools/restore.sh examples/tcl-g07-google-tv/debloat.txt com.google.android.apps.tv.launcherx
# Everything is DISABLED, not uninstalled. Comment out any line you want to keep.

# Tested 2026-10-20 on a real unit, applied in six batches with screenshots between them: Wi-Fi, Home, the Input
# key's source panel, Netflix, YouTube, Live TV and HDMI (from the launcher's Inputs menu) all kept working, and
# setupwraith, launcherx and dreamx stayed disabled after a reboot (unlike the G05). Launcher works.
# Stock launcher: com.google.android.apps.tv.launcherx; setupwraith's RecoveryActivity claims HOME at priority 1
# once it is gone. The Wi-Fi saved at setup belonged to android.uid.system, not setupwraith, so disabling
# setupwraith kept the network.
#
# Also tested 2026-10-19 on a second unit, UK firmware used in Brazil, build RP1A.200622.001 AR17, with the
# launcher as Home and through a reboot. Two things differ from AR20 there:
# - The Wi-Fi saved during first setup belonged to setupwraith, so disabling it made Android delete the
#   network and the TV dropped off Wi-Fi (and ADB). Pick the network again in Settings > Network; Settings
#   then owns it and it survives reboots. tools/disable.sh now checks the owner first and skips setupwraith
#   while it owns the network.
# - The adb shell may not write Android/data, so tools/theme.sh has to go through the launcher's
#   ThemeProvider (it falls back to it on its own when the plain copy is refused).
# TvInputManager reports AV as connected with nothing plugged in. com.tcl.notereminder was enabled on that
# unit, not disabled at the factory, so it is listed below.
#
# Also tested 2026-10-20/21 on a third unit in Brazil (product G07_4K_GB_NF, client TCL-LA-RTD51A-S1,
# software V8-R51AT01-LF1V126, incremental AR07, fingerprint TCL/G07_4K_GB_NF/G07:11/RP1A.200622.001/AR17,
# security patch 2024-12-05; Discussion #729):
# - Stage 1 disabled 9 packages in two conservative batches (waterfall.overseas, esticker, notereminder,
#   feedback, guard, then dashboard, partnercustomizer, messagebox, tv.tclhome_passive) while keeping the
#   stock launcherx as Home. Stage 2 disabled 25 more packages, installed the reference launcher
#   (INPUT_KEY_SERVICE=1 HOME_KEY_SERVICE=1) with the ClockDream screensaver, and disabled launcherx,
#   setupwraith (saved Wi-Fi belonged to android.uid.system, uid 1000) and dreamx.
# - Kept by choice on that unit: com.tcl.ttvs (firmware updates), voice (com.google.android.katniss,
#   com.tcl.assistant, com.google.android.tv.assistant), Chromecast (com.google.android.apps.mediashell)
#   and com.google.android.youtube.tvmusic. Physical HDMI/AV playback, OTA update arrival and live
#   tools/restore.sh rollback were not exercised in that session.
# - Only au.com.stan.and and tv.wuaki.apptv came disabled at the factory (com.tcl.smartalexa and
#   com.iqiyi.i18n.tv were not installed); com.google.android.videos and com.tcl.notereminder shipped
#   enabled.
# - Reboot check (tools/check.py): launcherx, setupwraith, dreamx and the other disabled packages stayed
#   disabled across a reboot, but AR07 firmware automatically re-enabled com.tcl.notereminder and
#   com.tcl.usercenter at boot. Adding both to hidden_apps in launcher/app/src/main/res/values/config.xml
#   hides them from the app grid without fighting the firmware on every boot.
#
# Remote (IR, /dev/input/event0 "mtkinp"; scancodes from getevent with the real remote):
# - Input (471, TV_INPUT) goes to TclPhoneWindowManager.startQuickPanelService, so it keeps working without
#   launcherx and needs no InputKeyService.
# - Gear (561, TCL_SET) became launcherx's quick settings panel, so it does nothing once launcherx is off.
#   HOME_KEY_SERVICE=1 with settings_key_scancodes 561 in config.xml brings it back.
# - Netflix (566, TCL_NETFLIX) and YouTube (569, TCL_YOUTUBE) are broadcasts that only launcherx answers, so
#   they do nothing once it is off. An accessibility service that matches those scancodes and starts the app
#   fixes both (verified with the real remote).
# Remote (Bluetooth, second AR20 unit, France; /dev/input/event3, vendor 0x0417 product 0x0304, Generic.kl):
# - Its buttons send other codes, and settings_key_scancodes 561 does nothing for them. Gear is KEY_FORWARDMAIL
#   (233, TCL_SET) and arrives as keycode 4077; Prime Video is HID usage 0x000c005f and arrives as keycode 4099.
#   `getevent -lt` while pressing a button tells the two remotes apart (event0 mtkinp or event3).
# - With HOME_KEY_SERVICE=1, this config.xml brought back Gear, Netflix, YouTube and Prime Video (verified with
#   the real remote): settings_key_keycodes 4077, and app_keys KEYCODE_TCL_NETFLIX:com.netflix.ninja,
#   KEYCODE_TCL_YOUTUBE:com.google.android.youtube.tv, 4099:com.amazon.amazonvideo.livingroom.
# tools/b64push.py worked here (md5 match). Screenshots of Live TV and HDMI are 0 bytes; Netflix's are black.
#
# Also tested 2026-10-20 to 10-24 on a fourth unit in Brazil, same software as the third (V8-R51AT01-LF1V126,
# incremental AR07, patch 2024-12-05), Bluetooth remote "TCL_RC902V_MG" on event3; launcher as Home through
# reboots and four days of use:
# - Gear sent KEY_FORWARDMAIL (233) as keycode 4077 here too; settings_key_keycodes 4077 with HOME_KEY_SERVICE=1
#   fixed it (enabled and bound for user 0, then pressed on the real remote). It was SystemUI's
#   TOGGLE_NOTIFICATION_HANDLER_PANEL, which only launcherx answers.
# - Wi-Fi: setupwraith owned one of the five saved networks (an old one, not the network in use) and Android
#   deleted only that one when setupwraith was disabled. Check the creator of every saved network, not just the
#   current one: `dumpsys wifi`, then the cname= of each.
# - com.tcl.micmanager and com.google.android.apps.nbu.smartconnect.tv were disabled for four days with no effect
#   noticed (voice was off by choice, so the mic was not used).
# - With com.tcl.channelplus off, the "free channels" stay listed with no picture: the Input panel's
#   "Pressione para Canais gratuitos" row and the TV app's channel list. `pm clear com.tcl.suspension` swaps
#   the panel's channel row for recent apps. The TV app's list is fetched by com.tcl.tv itself (it runs as
#   uid 1000) and is not kept in TvProvider, so nothing on the TV removes it short of DNS blocking; the owner
#   re-enabled channelplus and the channels played at once (streams from amagi.tv).
# - ttvs's update screen (Settings > System > About > Software update > Network update > System update) cannot
#   be started over adb (needs com.tcl.permission.START_CHECK_SYSTEMUPDATE) and blocks screenshots. With ttvs
#   enabled for the check, V8-R51AT01-LF1V126 was the latest version on 2026-10-20; ttvs was off otherwise.
# - Used RAM 150 s after boot: 1294 MB stock, 1004 MB debloated, 1019 MB with the launcher (MemAvailable
#   683 -> 662 -> 801 MB).
#
# Also tested 2026-10-25 on a fifth unit, a Hitachi CDH-LE554KSMART26 (TCL-built re-badge for Latin America,

# TCL Smart TV Pro, US (device G05, product G05_4K_US, board C05, MediaTek MT5889 / MT9615)
# Android 11 (Google TV), firmware AR2101, software AR68 (built March 2024) and AR71, 2.7 GB RAM
# Also sold as the TCL 55Q750G (AR71, on Wi-Fi), where both halves work: debloat and the launcher as Home.
#
# Apply:   TV_HOST=<tv ip> tools/disable.sh examples/tcl-g05-google-tv/debloat.txt
# Undo:    TV_HOST=<tv ip> tools/restore.sh examples/tcl-g05-google-tv/debloat.txt com.google.android.apps.tv.launcherx
# Everything is DISABLED, not uninstalled. Comment out any line you want to keep.
#
# Stock launcher: com.google.android.apps.tv.launcherx (pass it to restore.sh, the default is wrong here).
# Live TV app: com.tcl.tv (.TVActivity; keep it, it also owns HDMI/antenna playback, HDMI through
# com.tcl.tvinput's passthrough input). Keep com.tcl.tvinput, com.tcl.settings, com.tcl.system.server,
# com.tcl.keyhelp, com.tcl.autopair, com.tcl.tcl_bt_rcu_service (remote) and com.tcl.providers.config.
# Unlike the G10, com.tcl.ttvs ships enabled here. It carries TCL's BI analytics and Samba TV ACR, and on AR71
# also the TCL firmware updater (versionUpdateApp ... SystemUpdateActivity): comment it out to keep updates.
# The firmware re-enables com.tcl.usercenter and com.tcl.smartalexa at every boot (55Q750G, two reboots);
# everything else in the list stayed disabled.
#
# Known quirk, read before replacing the launcher. Whether disabling setupwraith sticks goes by the
# incremental build (ro.build.version.incremental), not by the model; all reports share the AR2101 build ID:
# - AR68 (US, the unit this list came from): this US build is the exception. With launcherx disabled,
#   com.google.android.tungsten.setupwraith/.RecoveryActivity claims HOME at priority 1 and Home lands on a
#   black, looping recovery screen. Shell cannot disable that component. Disabling the whole setupwraith
#   package worked until a reboot, after which this TV had it back in charge, unlike the MOOR2, QM6K and
#   Chromecast reports where the disable survives. launcher/build-and-install.sh refuses and rolls back
#   while Home resolves to setupwraith (docs/TROUBLESHOOTING.md, "The new launcher still doesn't own Home").
#   Recover with: pm enable com.google.android.apps.tv.launcherx; pm enable com.google.android.tungsten.setupwraith
# - AR71 (US, a TCL 55Q750G, 21 October 2026): the first run of build-and-install.sh on G05 firmware.
#   setupwraith stayed disabled across a reboot and Home stayed with the new launcher (mFocusedApp =
#   com.gathin.tvhome). Order: setupwraith first, while launcherx still owns Home, then build-and-install.sh,
#   which starts the new launcher and only then disables launcherx. On Wi-Fi, run
#   `tools/tv.py "dumpsys wifi | grep -o 'cname=[^ ]*'"` first: the network saved during first setup belonged
#   to setupwraith, so disable.sh skips it. Forget the network and join it again in Settings, typing the
#   password, until `cmd wifi list-networks` shows a new network ID (the first forget there did not take); it
#   then belongs to com.android.tv.settings and Wi-Fi survives the disable. Input, Settings, Netflix, YouTube,
#   Prime Video and the mic all worked with launcherx off and com.tcl.suspension kept, without
#   INPUT_KEY_SERVICE or HOME_KEY_SERVICE.
# - The G05_4K_GB units (tcl-65c735, and docs/devices/tcl-55c728-g05-4k-gb.md on AR28) kept setupwraith off
#   across a reboot too. The 55C728 report installed its own launcher, not with build-and-install.sh.
#   Compare ro.build.version.incremental before promising either outcome.
#   Contributed by damonearl (PR #73); AR71 findings from a 55Q750G.

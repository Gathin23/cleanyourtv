# Xiaomi Mi Box S (model MIBOX4, MDZ-22-AB, codename oneday, Amlogic gxl), Android TV 9 (SDK 28),
# firmware PI.3933 (built 2021-09-28), security patch 2021-07-05, 2 GB RAM, 1920x1080. Indian unit:
# PatchWall arrived through Xiaomi's update service.
# Fingerprint: Xiaomi/oneday/oneday:9/PI/3933:user/release-keys
#
# Apply:   TV_HOST=<box ip> tools/disable.sh examples/xiaomi-mi-box-s/debloat.txt
# Undo:    TV_HOST=<box ip> tools/restore.sh examples/xiaomi-mi-box-s/debloat.txt
# Everything is DISABLED, not uninstalled. Comment out any line you want to keep.
#
# A streaming box: no HDMI-in or tuner, so the Inputs menu has nothing to list; set live_tv_package empty in
# config.xml. Stock launcher: com.google.android.tvlauncher (the scripts' default).
#
# Notes from this box:
# - Leave alone: com.xiaomi.android.tvsetup.partnercustomizer (receives the remote's shortcut buttons as
#   GLOBAL_BUTTON, and runs the remote-pairing steps of setup), mitv.service (Xiaomi TvServer, persistent),
#   com.google.android.tungsten.setupwraith (remote pairing), com.droidlogic* (Amlogic system, Bluetooth).
# - USB debugging alone opens network ADB on port 5555 (service.adb.tcp.port=5555).
# - USB debugging CUTS POWER to the USB port: with sys.usb.config=adb, /vendor/etc/init/hw/init.amlogic.usb.rc
#   writes 0xFDFFFFFF to register 0xc883443c and the port switches to ADB device mode, so a USB speaker or drive
#   goes dead; sys.usb.config=mtp (debugging off) writes 0xFD7FFFFF and powers it again. Turn debugging off when done.
# - cmd package set-home-activity needs the component on Android 9 (com.gathin.tvhome/.MainActivity).
# - Location is off, so Android 9 hides the Wi-Fi name from apps and the launcher's pill just says "Wi-Fi".
# - Remote (Vendor_2717_Product_32b9): the Netflix key still opens Netflix; BUTTON_2 opened Live Channels and
#   does nothing once it is disabled; BUTTON_3/4 and ALL_APPS did nothing even on stock. No crashes either way.
# - Survives a reboot: nothing is re-enabled at boot, the launcher stays Home. Free RAM after boot went from
#   about 770 MB to 1.15 GB.
# - A process of the disabled stock launcher can linger until the next reboot; `am force-stop` clears it.
#
# Second unit (same PI.3933 build), 2026-10-21. Details: docs/devices/xiaomi-mi-box-s.md
#   - Every package below was present and disabled cleanly; nothing was re-enabled after a reboot.
#   - Nothing was disabled beforehand: the "already disabled" apps at the bottom were all enabled there.
#     Google Play Music (com.google.android.music, closed in 2020) was installed too.
#   - The saved Wi-Fi belonged to android.uid.system, not setupwraith; setupwraith was not needed.
#   - The Apps button (scancode 580, ALL_APPS) opens Home with the launcher's HomeKeyService
#     (build-and-install -HomeKeyService). Home, Back, voice and Netflix work without it.
#   - On remotes with a Live button (scancode 399), disabling com.google.android.tv triggers
#     partnercustomizer to open Google Play unless remapped via app_keys ("scan:399:<package>",
#     build-and-install -InputKeyService).
#
# Third unit (same PI.3933 build), Turkey, 2026-09-17 to 2026-10-24 (37 days):
#   - Xiaomi's update service enables PatchWall again. Its component applife.LifeKeeper installs
#     com.mitv.tvhome.atv again about 3 minutes after you disable it. The install changes the package
#     state to enabled. Logcat shows "PatchWallUpdateService: ... LifeKeeper ... package:com.mitv.tvhome.atv
#     event:INSTALL". On this unit, PatchWall was disabled in one batch and the updater in a later batch.
#   - For this reason, this list disables the update service before PatchWall. After the updater was disabled,
#     PatchWall stayed disabled for 37 days and after each reboot.
#   - Five minutes after you apply the list, do a check: compare `pm list packages -d` with this file.
#
# Fifth unit (same PI.3933 build), 2026-10-25. Details: docs/devices/xiaomi-mi-box-s.md

# Content home and HOME stub, applied after the replacement launcher owned Home (2026-10-25 session).
# The boot flow and the physical Home key on this firmware route straight to the Youku home and eat
# KEYCODE_HOME before Android's default handling and before the accessibility key filter (Android 13):
# with Youku disabled, the Home button did nothing. So Youku is RE-ENABLED as a stepping stone and the
# launcher's stock_home_redirect bounces back to it the moment the Youku home appears (a short flash).
# It is hidden from the launcher grid (hidden_apps) and stays otherwise unused.
# com.haier.tv.provision stays disabled: enabled, it claims HOME at priority 1, and
# cmd package set-home-activity reports Success while resolve-activity still returns it.
# com.haier.tv.provision                              # preferred HOME stub; disabled after the launcher took Home
#
# What the firmware does, from the session recorded in #2955:
# - One early boot turned five of these back on (deskclock, calendar, contacts, camera2, appversion) and
#   the next run kept them off: it is the firmware reconciling its own package list, and re-applying the
#   list is safe. check.py reports the same thing after an update.
# - It clears third-party accessibility settings at every boot and on the standby force-stop, so the
#   launcher's key helper has to be put back by the theme's restore_key_services, and with key_filter
#   on it is the only thing that keeps the physical Home key from landing on the Youku desktop.
# - The stock installer UI is an AliOS plugin hosted inside the Youku process: the com.aliott.* and
#   com.yunos.* hosts stay enabled (they are not in this list), and Youku itself stays on as the Home
#   stepping stone the launcher bounces off. Disabling Youku leaves the Home key dead and the installer
#   hung on its check phase.
# - The owner also disabled 57 of Youku's own components with `pm disable --user 0 <package>/<component>`
#   (the installer still verified after it). Component disables are not list lines: tools/disable.sh
#   sends package names only, and `pm disable-user` on a component answers "new state: default" on this
#   firmware while `pm disable` works.
# - The userspace is 32-bit (armeabi-v7a, zygote32 on a 64-bit-capable MT9633), so arm64-only APKs fail
#   with INSTALL_FAILED_NO_MATCHING_ABIS.

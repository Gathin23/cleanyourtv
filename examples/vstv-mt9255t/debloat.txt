# WARNING, this is how this board bricks: com.vstv.fbhome is VsFallbackHome, the only home in the
# firmware declared android:directBootAware="true". PackageManager hides everything that is not
# direct-boot-aware while user 0 is still locked, so fbhome is the only HOME activity
# startHomeActivityLocked can launch before the unlock; the stock launcher cannot stand in for it.
# Disable fbhome together with com.vstv.mercurylauncher and systemReady() logs "No home screen
# found", user 0 never leaves State: BOOTING, init.svc.bootanim never stops and the TV sits on the
# Android wordmark forever. Ethernet still comes up at 100 Mbps in that state but receives zero
# bytes and port 5555 stays closed, so network adb cannot rescue you - and re-enabling only the
# stock launcher does not help, because it is not direct-boot-aware either.
# Never disable com.vstv.fbhome. Recovery is USB only: adbd starts long before the framework and
# `adb root` works on this build, then pm enable com.vstv.fbhome + reboot.
# See docs/TROUBLESHOOTING.md, "The TV stays on the boot logo after a list, and disabling the only
# Home app is enough to do it": this board is the CVTE case that bullet describes.
#
# Keep: com.vstv.input (VsTvInput - DTV/HDMI inputs), com.vstv.septembersettings (the Settings app),
# com.vstv.global.service (GlobalUI - OSD/volume/toast surface), com.vstv.mercurylauncher (stock
# launcher, the restore.sh default home), com.vstv.fbhome (fallback home), and all com.mediatek.*
# (tvinput, autopair, wwtv.tvcenter). Nothing below touches the input path or the UI surface.
# Hotstar, Nuvio, Cloudstream, CloudStream prerelease, BROWSER and com.activitymanager are
# side-loaded apps on this unit, not firmware - they are not listed here.

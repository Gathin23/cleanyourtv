# Tested 2026-10-20 on a real unit, applied in the seven batches below with a screenshot after each, then a

# launcher's Inputs menu, app launches and playback with AdGuard Private DNS all worked, and every package
# stayed disabled after the reboot. Lived with for one day so far. launcher/ installed with the default

#
# Stock launcher: com.google.android.apps.tv.launcherx. Live TV / HDMI: com.tcl.tv (TVActivity) with inputs from
# com.tcl.tvinput (tuner, HDMI 1-3, AV). The launcher's default live_tv_package is MediaTek's, so the Inputs menu
# has no Live TV row until a theme sets "live_tv_package": "com.tcl.tv". config.json in this folder sets it,
# the gear button and the app buttons described under "Second unit" below; push it with:
# TV_HOST=<tv ip> tools/theme.sh examples/tcl-g03-google-tv
# Already disabled at the factory: au.com.stan.and (Stan), tv.wuaki.apptv (Rakuten TV); the second unit below
# also had com.tcl.smartalexa off at the factory.
#
# Before batch 6 (setupwraith): on this unit the Wi-Fi saved during first setup belonged to setupwraith
# (`dumpsys wifi | grep -o 'cname=[^ ]*'`), so disabling it would have deleted the network. Forgetting the
# network and joining it again in Settings moved it to com.android.tv.settings; then disabling setupwraith kept
# Wi-Fi. tools/disable.sh skips setupwraith while it owns the network.
#
# Remote (Bluetooth "TCL_RC902V_MM", Generic.kl):
# - Input keeps opening TCL's source panel (com.tcl.suspension) without launcherx; no InputKeyService needed.
# - Gear is scancode 233 (KEY_FORWARDMAIL, HID 0x0c0055), mapped to TCL_SET, keycode 4077. Only launcherx
#   answered it, so it does nothing once launcherx is off. HOME_KEY_SERVICE=1 at install plus
#   "settings_key_keycodes": [4077] in the theme brings it back (verified with the real remote); with
#   "settings_key_panel": true it opens the launcher's quick settings panel over any app.
# - `input keyevent SETTINGS` opens Android's version easter egg here; inject 176 instead.
#
# Second unit, 2026-10-21, same AR09 build, applied in the batches below with a screenshot after each and then
# rebooted with launcherx off: the list minus Netflix and Prime Video, minus the factory-off smartalexa, plus
# launcherx (38 packages) stayed disabled, and HDMI, Netflix playback, the remote and Wi-Fi all worked.
# AdGuard's Private DNS (private_dns_mode hostname) changed nothing for playback. Two things differ:
# - Its Bluetooth remote is "TCL_RC902V_M1" (also /dev/input/event3, Generic.kl), not the "TCL_RC902V_MM" above.
#   Netflix (HID 0x0c0051, TCL_NETFLIX), YouTube (0x0c0057, TCL_YOUTUBE) and Prime Video (0x0c005f, keycode
#   4099) are broadcasts only launcherx answers, so all three do nothing once it is off. `getevent -lt` prints
#   the HID usage and the Linux key under each button, which is how the two remotes are told apart.
# - HOME_KEY_SERVICE=1 with the app_keys in config.json brings all three back (verified with the real remote;
#   a button whose app you disabled still opens nothing). Gear is keycode 4077 on this remote too, so
#   settings_key_keycodes and settings_key_panel above apply unchanged.
# setupwraith owned the Wi-Fi on this unit as well, and this order worked: forget and re-join the network,
# disable setupwraith while launcherx still owns Home, run launcher/build-and-install.sh, switch the
# screensaver, then disable dreamx. Home landed on the new launcher straight away (mFocusedApp checked), with
# no RecoveryActivity in between.
#
# US firmware unit, 2026-10-25: TCL Smart TV Pro G03_4K_US (BeyondTV4, Realtek rtd288o / R51MT05,
# software V8-R51MT05-LF1V813), Google TV 11, build RP1A.200622.001 GTV93, security patch 2023-10-05, client
# TCL-NA-RTD51M-S1. The packages of groups 1-3 still enabled on this unit were disabled one per shell call, then
# rebooted: Wi-Fi and internet stayed up, Settings opened and every package stayed disabled. Lived with for a few
# days. This unit kept launcherx and setupwraith (setupwraith owned the Wi-Fi here too), so group 6 and the
# launcherx line were not applied. Found on this unit:
# - com.tcl.xian.StartandroidService is also how TCL's updater gets the device number (dnum). With it disabled,
#   Settings > About > Software Update > Network Update fails with "Local network or server abnormal, please check
#   the network and try again" while the network is fine (logcat: "dnum is null!"). If you turned it off, to check for an update enable it,
#   reboot once, run the check, then disable it again (docs/TROUBLESHOOTING.md).
# - com.google.android.apps.tv.dreamx is more than the promo screensaver: it also hosts Google TV's Google Home panel
#   (SmartHomeMainActivity: lights and other devices in the quick settings). Disabling it removes that panel. It also
#   loads the panel's account through com.google.android.apps.tv.launcherx, so with launcherx off the panel opens and
#   closes at once: if the household uses Google Home lights, keep launcherx enabled as well and hand Home to the new
#   launcher with stock_home_redirect (docs/TROUBLESHOOTING.md, #1653).
# - Apps only mode (Settings > Accounts & Sign In > account) also hides the Google Home panel on this firmware.
#

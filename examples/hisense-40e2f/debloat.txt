# ADB: turn on Developer options, then Network debugging (this set has no USB port wired for ADB), and

#
# KEPT ON PURPOSE
# - com.jamdeo.tv.vod, the stock VIDAA Home. It answers the input-source handover on this board, so it
#   stays enabled even after a replacement launcher is set as Home with `cmd package set-home-activity`.
# - com.jamdeo.tv.livetv and com.jamdeo.tv.service, the Live TV app and its middleware. `dumpsys tv_input`
#   lists no inputs at all on this build, so the app's own source panel is the way to reach HDMI 1 and 2.
# - com.hisense.tv.tiletransition. Not just animation: AppTransitionManager.startSourceFromLauncher binds
#   to its TileAnimationService, and with this package disabled HDMI 1/HDMI 2 switching stopped working
#   (tested on this unit; re-enabled, and the ports switched again).
# - Casting, all of it: com.multiscreen.airplay (AirPlay), com.hisense.wifidisplay (Miracast),
#   com.hisense.multiscreen.screenhelper and com.ms.weshare (DLNA).
# - com.jamdeo.tv.mediacenter, the media player, and the input methods, Settings and every com.android.*
#   core package.
#
# FIRMWARE KEEP-ALIVE: com.android.browser, com.android.calendar, com.android.camera2, com.android.contacts,
#   com.android.deskclock and com.android.music come back enabled after every reboot on this build. They are
#   commented out below instead of being fought with `check.py --fix`.
#
# Applied in small batches with a screenshot after each; reboot-checked four times; the owner confirmed the
# physical feature checks afterwards (HDMI 1/HDMI 2 switching, Live TV, casting, remote).

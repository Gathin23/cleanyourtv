# Launcher handover, two things that differ from the script's assumptions on this TV:
# 1. The first cold start of the freshly installed, not yet compiled launcher takes longer than the
#    10 s `am start -W` waits on this 32-bit MT5887, so build-and-install.sh stops with
#    "Status: timeout" although the launcher came up fine (it was the resumed activity and drew its
#    first screen). The remaining steps (pm grant, cmd package compile -m speed, set-home-activity)
#    were run by hand. Updating the already installed launcher later started in 2.2 s and the
#    script ran through on its own.
# 2. The stock launcher's HOME filter has priority=2, a third-party launcher's always 0, and Android
#    picks the higher priority before it looks at the preferred activity. So with the stock launcher
#    still enabled, set-home-activity succeeds and the HOME role moves to com.gathin.tvhome, yet the
#    Home key still opens com.google.android.tvlauncher. The new launcher only takes over once the
#    stock one is disabled, as note 3 in examples/philips-55oled707 found on the Android 11 board.
#
# After each batch: logcat -c, 30 s of an idle TV, logcat -d, then group lines by shape and look
# for anything repeating several times a second (see quirk 5 in examples/philips-50pus8517). The
# only loop on this TV before and after is adbd retrying the USB gadget about once a second while
# USB debugging is on; it is not caused by the debloat.
# A soundbar on HDMI ARC that goes to standby on its own silence timer sends <Set System Audio Mode>
# off and <Terminate ARC>, and the TV shows "TV reproduktory aktivní" (TV speakers active). With
# Home on screen and nothing playing that happens during testing too; it is the soundbar, not the
# debloat.

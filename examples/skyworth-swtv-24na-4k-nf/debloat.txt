# Google TV 14 (API 34), build UKN6.260116.056, security patch 2026-04-01. About 1.8 GB RAM, armeabi-v7a.
# ro.product.model="SWTV-24NA-4K NF" (ro.product.vendor.model=SWTV-24AE-4K). Same eleonas platform as

#
# Apply:   TV_HOST=<tv ip> tools/disable.sh examples/skyworth-swtv-24na-4k-nf/debloat.txt
# Undo:    TV_HOST=<tv ip> tools/restore.sh examples/skyworth-swtv-24na-4k-nf/debloat.txt com.google.android.apps.tv.launcherx
# Everything is DISABLED, not uninstalled. Comment out any line you want to keep.
#
# Applied in small batches on 2026-10-19 with a screenshot after each, then a custom launcher
# installed and Home, Inputs (HDMI and Live TV) and YouTube playback checked the same day. Not yet
# lived with for days; if something breaks, re-enable it with `pm enable <package>` and please report it.
#
# Stock launcher: com.google.android.apps.tv.launcherx; setupwraith RecoveryActivity also claims HOME
# (priority 1), so it is in this list.
# Live TV app: com.cltv.hybrid (iWedia CanaliTV, com.iwedia.cltv.MainActivity, labelled "Live TVˣ");
# set it as live_tv_package. HDMI, composite and analog inputs are com.mediatek.tis; ATSC tuner
# com.mediatek.dtv.tvinput.atsctuner.
# Disabled from the factory, so not listed (restore.sh would turn them ON):
# com.mediatek.dtv.tvinput.isdbtuner, com.mediatek.dtv.tvinput.dvbtuner, com.mediatek.tv.retaildemo,
# com.mediatek.opapp, com.mediatek.tv.oneworld.tvcenter.
#
# Quirks on this firmware, all checked on the TV:
# - Only Wireless debugging: port 5555 stays closed. Pair once with the stock adb (Developer options >
#   Wireless debugging > Pair device with pairing code, `adb pair <ip>:<port> <code>`). The stock adb
#   connected fine from macOS here; adb tracks the TV by its mDNS name
#   (adb-<serial>._adb-tls-connect._tcp), so it survives port and IP changes.
# - Android switches Wireless debugging off whenever Wi-Fi drops; switch it on again and adb reconnects
#   without a new pairing code.
# - The Wi-Fi network had been saved during first setup, so disabling setupwraith deleted it (see the
#   warning at the bottom). The TV dropped off Wi-Fi mid-command; it took a USB keyboard to rejoin.
# - YouTube playback can be screenshotted on this TV; HDMI and Live TV cannot (protected layer).
# - A second Google TV profile is a second Android user, and this board's key service
#   (com.smartdevice.global.service, kept) then takes a provider client for launcherx's LiveTvContentProvider
#   on every gear/Input hotkey: with launcherx disabled it throws, and RescueParty climbs to the level that
#   switches the launcher's accessibility helpers off. Seen on a Coocaa Y74 Pro 65" (SW10_TG, Google TV 14,
#   UKN4.250714.140). Run `pm list users` first, and see
#   docs/TROUBLESHOOTING.md#app-buttons-crash-the-tvs-own-key-service-on-a-set-with-a-second-user-skyworthcoocaa
#
# Kept on purpose: com.cltv.hybrid / com.cltv.mal (Live TV), com.mediatek.tis and the ATSC tuner
# (inputs), com.mediatek.tv.agent (hot keys, Netflix key, one-key menu), com.mediatek.extservice,
# com.mediatek.autopair, com.smartdevice.global.service (BLE remote, battery, find my remote, hot keys),
# com.smartdevice.dailyshortcut (quick menu and source sorting), com.smartdevice.duplebluetooth,
# com.smartdevice.factory, org.liskovsoft.androidtv.rukeyboard and com.google.android.inputmethod.latin
# (keyboards), Play Store, Play Services.
# Left alone because their purpose is unclear: com.smartdevice.dailymanage ("Daily Manage") and
# com.smartdevice.myapp ("Daily Key"); examples/philips-smart-4k-google-tv disables both.
# Kept by owner's choice: com.google.android.apps.mediashell (Chromecast), com.mediatek.dialservice (DIAL),
# com.smartdevice.dtv.icast (Miracast/DLNA), com.ionitech.airscreen (AirPlay receiver from Play),
# com.audiocn.karaoke.global.micmanager and com.loostone.tuning (karaoke mic), com.mediatek.tv.systemupdater
# (firmware updates), com.tianci.localmedia (USB media player), all streaming apps.

# What this unit adds to the 50PUS8517 / 55OLED707 notes:
#
# 1. Already disabled at the factory on this French unit: the UK Freeview apps (uk.co.freeview.*,
#    org.droidtv.freeviewplayers), Apple TV, YouTube Music AND org.droidtv.aurora. The 50PUS8517 notes say a
#    disabled aurora leaves xtv retrying every 201 ms; on this unit an idle 30 s log shows 0 handleConnectAurora
#    and 0 connectCotextService lines, so aurora was left as the factory set it.
# 2. Packages the earlier lists do not have, checked with `dumpsys package` (none launched):
#    org.droidtv.astrahdplus (HD+ German satellite info pages), io.mimi.tvapp + io.mimi.sdk.service (Mimi
#    hearing-personalised sound), org.droidtv.dropboxprovider (Dropbox in Media). All three disabled cleanly;
#    sound, Media and live TV unaffected. Not touched: org.droidtv.fastip (IP channel installer; the 75PUS8505
#    notes say SOURCES dies without it), org.droidtv.sam / csm (service menus), dukservice, usbbreakin, factory.
# 3. tools/tv.py (adb_shell) gets no answer until it is accepted at the TV's own "Allow USB debugging?" prompt,
#    even with the same key the stock adb already uses; tools/theme.sh hangs on it until then. The stock adb works.
# 4. OLED screensaver: tvsystemui draws a moving Philips logo over everything after about 5 minutes of a still
#    picture, and once it is up it stays on top of the launcher's own idle clock. home_idle_clock_minutes must
#    therefore be 4 or less here; with the clock already up (it moves every minute) the logo did not come back
#    in more than 7 minutes. Injected keys over adb do not dismiss the logo, and the shell cannot write to the
#    remote's input device on this firmware (sendevent: Permission denied), so test it with the real remote.
# 5. The TV powers on to the last source in use: switched off from Home it comes back on Home, switched off on
#    an HDMI input it comes back on that input. It only resumes the PlayTvActivity it left, which sends its
#    window event once the input has a picture (about 5 s), if at all, so power_on_home alone is late or
#    misses it. power_on_home_always (with HOME_KEY_SERVICE=1) brings Home up about 1 s after wake, from an
#    HDMI input or an app. After installing the launcher and after a theme push (which force-stops it),
#    switch enabled_accessibility_services off and on again, or the helper stays in "Crashed services".
# 6. Chromecast (mediashell) re-enables itself, as on the 50PUS8517: left out.
# 7. show_stats and the CPU figure: apps cannot read the CPU load here. /proc/stat and /proc/loadavg are
#    denied to apps on this Android 11 build, and the kernel has no cpuidle (no
#    /sys/devices/system/cpu/cpu0/cpuidle). The load average read over adb sits around 36 on 4 cores at
#    idle, so it would not be a usable stand-in anyway. Memory and storage read fine; the CPU part is left out.
#
# Verified with the real remote after the list and the launcher: channel change, TV guide, SOURCES drawer and
# HDMI switching, sound and Ambilight all work; Home opens the replacement launcher. After a reboot, waiting
# 15 s first (quirk 1), all 26 packages were still disabled and nothing came back. Free memory at idle on Home:
# about 780 MB stock, about 1.1 GB with this list and the launcher.
#
# Kept on purpose (owner's choice): Google Assistant (katniss), Play-Fi, IP control, DLNA, YouTube, Prime Video.

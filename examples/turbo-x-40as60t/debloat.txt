# Same Vestel menlo board as examples/jvc-android-tv-menlo, whose Finlux unit runs this exact build
# (UKNV.260914.002/16342942) after its Android 14 update; a separate folder because it is another brand
# and model, cleaned straight on Android 14, with a different set of owner choices. Same Vestel services
# as examples/cecotec-shandao. UK-market firmware: every uk.co.freeview.* package already ships disabled.

# Apply:   TV_HOST=<tv ip> tools/disable.sh examples/turbo-x-40as60t/debloat.txt
# Undo:    TV_HOST=<tv ip> tools/restore.sh examples/turbo-x-40as60t/debloat.txt
# Everything is DISABLED, not uninstalled. Comment out any line you want to keep.

# Stock launcher:  com.google.android.tvlauncher (classic Android TV, not Google TV)
# Live TV app:     com.mediatek.wwtv.tvcenter
# Updates:         no separate firmware-update package; updates live in Settings.
#
# KEEP, even though the names look like bloat (checked on this TV):
# - fusion.android.tv.demo: as on the JVC menlo, NOT as on the Cecotec. It receives
#   com.mstar.android.intent.action.TV_INPUT_BUTTON, i.e. the remote's Input key.
# - com.google.android.tungsten.setupwraith: owns the Wi-Fi network saved at first setup
#   (dumpsys wifi shows cname=com.google.android.tungsten.setupwraith); disabling it deletes that
#   network and takes the TV off Wi-Fi and ADB. tools/disable.sh refuses it anyway.
# - com.vestel.tv.keycontroller: receives android.intent.action.GLOBAL_BUTTON (remote's app keys,
#   the star "favourite" key).
# - com.mediatek.android.leanbacklauncher.partnercustomizer, every other com.mediatek.*,
#   mediatek.factorymenu.ui and com.mediatek.tv.factory (never started), com.vestel.tv.service /
#   backlight / eib (E-User Manual), com.vestel.overlay.*, com.dolby.android.audio.service,
#   Play Store, Play Services, Gboard, TTS.
# - com.mediatek.wwtv.mediaplayer (MMP, USB media player): kept by choice.
# - com.cltv.fast (LiveTV+, iWedia FAST channels) and YouTube Music: kept by choice.
#
# Status: disabled in six batches on one TV on 2026-10-26 and 2026-10-27 (the last two lines after
# launcher/ took Home), screenshot after each batch, two reboots with `pm list packages -d` unchanged.
# Checked on the real remote by the owner: Input key, HDMI switching, Live TV, Home, Netflix and YouTube
# keys all work. In daily use since then (about two weeks by 2026-11-10) with nothing re-enabled
# and no problems seen.
#
# Quirks on this firmware:
# - screencap works over ADB (unlike the JVC menlo).
# - ro.adb.secure = 1: port 5555 shows the "Allow" prompt.
# - tools/disable.sh's input-driver guard skips android.autoinstalls.config.vestel.coma and
#   com.android.wallpaperbackup (no permission block in dumpsys). Both left enabled; not listed.
# - After the new Home took over, the remote's Prime Video, Google Play, Menu and star+1 keys did
#   nothing (Netflix and YouTube still worked). getevent -lt scancodes: Prime Video 504
#   (KEY_BRL_DOT8), Google Play 505 (KEY_BRL_DOT9), Menu 139 (KEY_MENU), star+1 212 (KEY_CAMERA).
#   Mapped with HOME_KEY_SERVICE=1 and config.xml app_keys scan:504 / scan:505 / scan:212 plus
#   settings_key_scancodes 139 (see README.md here). Holding Volume+ still ramps with the helper on.
# - At power-on the TV lands on Home by itself: no power_on_home or boot_to_live_tv needed.

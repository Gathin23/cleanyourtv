# Bell Fibe TV (ARRIS VIP7802, codename vip7802_bell), Android TV 11 (SDK 30),
# firmware RTT4.240509.001 (build 11.02.02.02.160-RC.149, release-keys).
# This is Bell Canada's IPTV set-top box, not a TV: Bell's launcher and remote key handling
# stay, and this list leaves the HDMI/CEC and Netflix-key packages alone (see below).
#
# Apply:   TV_HOST=<box ip> tools/disable.sh examples/bell-fibe-tv-vip7802/debloat.txt
# Undo:    TV_HOST=<box ip> tools/restore.sh examples/bell-fibe-tv-vip7802/debloat.txt
# Everything is DISABLED, not uninstalled. Comment out any line you want to keep.
#
# Stock launcher: com.custom.tvlauncher (Bell/ARRIS, not AOSP's com.google.android.tvlauncher).
# There is no separate Live TV package: Fibe content plays through ca.bell.chiclet.fibehelper,
# a real content app (see "Not disabled" below), and this box registers no
# android.media.tv.TvInputService at all.
#
# This box does not carry much ARRIS/CommScope bloat once content apps are left alone: the default
# list below is 13 packages - telemetry, two stub apps with no logic at all, and five Google TV
# services most owners would not miss (Play Games, Play Movies & TV, YouTube Music, Android TV's
# own feedback reporter, and the stock recommendation-row service, which this box's own launcher
# doesn't even read). Each of those five is still a real, separate thing, not telemetry; comment
# out any line below if you want it back - that's the convention this repo's other lists use for a
# package that's genuinely a personal call (see examples/anker-nebula-d2140, examples/asus-m1g for
# the same pattern: disabled by default with a comment, not held back as opt-in).
#
# It does not touch content apps, including the ones Bell preloaded (CTV, TSN, Noovo, TOU.TV, the
# Weather Network, iHeartRadio, Tubi, the Fibe player itself): those are free, ad-supported services
# real people use, the same way Fire TV lists in this repo keep Prime Video, Amazon Music and Luna
# by default and only flag them as the owner's own choice to remove.
#
# A separate, opt-in block lower down holds mainstream streaming apps (Netflix, Prime Video,
# YouTube) and three ARRIS features with a minor, skippable function (UPnP/DLNA, the customizer's
# resource overlay, Play Auto Install) - the streaming apps the same way examples/acer-ar3-r3 and
# examples/dexp-a651 in this repo offer Netflix and Prime Video as removable, for an owner who
# genuinely doesn't use one. Assistant voice search, Chromecast casting and the phone-as-remote app
# are NOT in that block: unlike UPnP or Play Auto Install, those are mainstream features most owners
# would reach for and miss immediately, so they're not offered at all - see "Kept deliberately" at
# the end. Six other ARRIS/CommScope packages this list also looked at are not in this file at all,
# in any form either: each declares a real feature (factory reset, diagnostics, find-my-remote,
# network setup, remote-key/power-button/HDMI-CEC handling), and a debloat list is for bloat - see
# "Kept deliberately" for what each one does and why it's excluded, not just held back.

# Kept deliberately, not in this file at all - needed by most people, not offered even as opt-in:
# - com.google.android.katniss (Assistant voice search from the remote's mic button),
#   com.google.android.apps.mediashell (Chromecast casting from a phone/laptop) and
#   com.google.android.tv.remote.service + .rro (lets a phone act as a second remote/keyboard):
#   mainstream features most owners would reach for and miss immediately, not minor conveniences
#   like UPnP or Play Auto Install. An earlier draft offered these three as opt-in; moved here
#   instead, the same tier as the physical remote and HDMI-CEC below.
# - com.arris.globalkeyactions: requests ca.bell.fiberemote.permission.BUTTON and
#   com.netflix.ninja.permission.NETFLIX_KEY, the Bell remote's Netflix key and button routing.
#   Disabling com.netflix.ninja above does not touch this package either way.
# - com.broadcom.nrdphelper: requests android.permission.HDMI_CEC.
# - com.apple.atve.androidtv.appletv: preloaded Apple TV app with EPG write access; content, not
#   telemetry, same as the Bell-preloaded apps above.
# - com.custom.tvlauncher: the only package that answers HOME on this box; disabling it before a
#   replacement is installed leaves nothing to start.
# - com.google.android.tungsten.setupwraith: Google's first-run setup wizard. A factory reset
#   restores the system partition to its factory image, which brings this package straight back
#   regardless of any pm disable-user state beforehand, so disabling it today buys nothing that
#   survives the one event (a reset) where it would matter again. What's left is only the downside:
#   on this box the saved Wi-Fi network had already been forgotten and rejoined and no other
#   installed app answered HOME, so tools/disable.sh's Home guard let a disable through without
#   FORCE_SETUPWRAITH=1 - but on a box where it still owns the Wi-Fi network, disabling it deletes
#   that network, and on Google TV it can crash-loop system_server if no other launcher answers
#   HOME yet. Dead weight once setup is done, real risk for no lasting gain, not worth offering.
# - com.arris.gtvs (factory reset: MasterClearReceiver), com.arris.chmframework (diagnostics and
#   developer unlock: DiagReceiver, DevUnlockReceiver), com.commscope.rcu.bell (the remote's own
#   app: find-my-remote, remote firmware upgrade), com.commscope.android.fti.bell.merlin (the
#   out-of-box network/Wi-Fi setup wizard), com.commscope.network.bell.merlin (a network-diagnostics
#   screen), com.commscope.nexusservice (RECEIVE_KEY_PRESS, RECEIVE_POWER_BUTTON_OVERRIDE,
#   SWITCH_DISPLAY_MODES, HDMI_CEC), com.arris.customizer (the Netflix remote key, reboot/recovery
#   permissions) and com.arris.remoteservice (most likely the Bluetooth-remote pairing helper): an
#   earlier draft of this list offered all eight as opt-in. That was also wrong - a debloat list is
#   for bloat, and none of these is bloat: they're normal device functionality (factory reset,
#   diagnostics, finding a lost remote, Wi-Fi setup, network troubleshooting, remote/power/HDMI-CEC
#   input), the same category CONTRIBUTING.md excludes for AOSP's own core packages. They're not in
#   this file in any form.
